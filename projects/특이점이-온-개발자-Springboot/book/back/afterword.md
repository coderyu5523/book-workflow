# 마치며

이 책은 요청 하나를 받아 처리하는 일이 왜 그렇게 번거로운가라는 물음에서 출발했습니다. 주소를 직접 잘라 분기하던 코드를 리플렉션으로 걷어내고, 그 위에 게시판을 올리고, 예외 처리와 DTO로 응답을 다듬고, 인증으로 요청자를 식별하고, 마지막에 댓글로 두 테이블을 이었습니다. 기능을 하나씩 더한 것처럼 보이지만, 우리가 한 일은 스프링이 대신 처리하던 자리를 하나씩 열어 본 것입니다.

이제 책을 덮고 실제 프로젝트를 열면, 여기서 다룬 예제보다 훨씬 많은 어노테이션과 설정 파일을 마주하게 됩니다. 이름조차 처음 보는 것들 앞에서 다시 막막해질 수도 있습니다.

하지만 겉이 두꺼워졌을 뿐, 안에서 벌어지는 일은 우리가 직접 만들어 본 것과 다르지 않습니다. 어딘가에 붙은 표식을 읽어 실행할 코드를 찾고, 객체를 만들어 필요한 곳에 넣어 주고, 데이터베이스와 객체 사이를 오갈 뿐입니다. 동작이 이해되지 않을 때 무엇이 이 코드를 실행했는지 되짚을 수 있다면, 낯선 코드 앞에서도 시작점을 잡을 수 있습니다.

프레임워크를 공부하는 이유는 프레임워크를 잘 다루기 위해서만은 아닙니다. 반복되는 일을 넘기고, 정말 만들고 싶은 기능에 시간을 쓰기 위해서입니다. 오픈이가 게시판을 만들 수 있게 된 것도 서버 뼈대를 직접 만들기를 포기한 다음이었습니다.

앞으로도 막히는 날은 옵니다. 그때 처음부터 다 알아야 한다고 자신을 몰아세우지 마세요. 로그를 더 읽고, 메서드를 따라 들어가 보면 됩니다.

이제 여러분 차례입니다.
