# 1.1 통합 테스트란?

> **통합 테스트(Integration Test)는 단위 테스트를 통과한 모듈들이 실제 환경처럼 함께 동작하는지 검증하는 단계입니다. 모듈 간의 인터페이스와 데이터 흐름을 확인하여, 시스템이 요구 사항을 충족하고 예상대로 작동하는지 테스트합니다.**
> 

커피 머신으로 예를 들어보겠습니다. 커피 머신에는 두 가지 핵심 기능이 필요합니다. 

한 가지는 커피콩을 약 1cm 크기로 고르게 분쇄하는 기능, 다른 한 가지는 1cm 크기로 분쇄된 커피콩으로부터 커피를 추출하는 기능입니다.
각 기능을 별도의 모듈로 독립적으로 구현하고 테스트한 후, 두 모듈을 하나로 연결하면 커피 머신이 완성됩니다.

<aside>
💡

**만약 커피콩 분쇄 모듈이 1cm가 아닌 0.5cm 크기로 분쇄한다면 어떤 일이 생길까요?**

**각 모듈은 정상적으로 동작할 것입니다. 그러나 두 모듈을 하나로 연결했을 때는 오류가 발생하게 될 것입니다.**

**이처럼 각 모듈이 독립적으로는 정상적으로 작동하더라도, 전체 시스템이 올바르게 동작하는지 확인하기 위해 통합 테스트가 반드시 필요합니다.**

</aside>

MyRestDoc를 다음과 같이 작성합니다. MyRestDoc 클래스는 실제 서버를 구동하지 않고,
MockMvc를 이용해 가상의 MVC 환경에서 컨트롤러를 테스트할 수 있도록 구성된 베이스 클래스입니다.
또한 통합 테스트 이 API 문서 자동 생성을 지원하기 위한 기본 설정을 포함하고 있습니다.

**MyRestDoc.java**

```java
package com.metacoding.springv2;

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.extension.ExtendWith;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.restdocs.AutoConfigureRestDocs;
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc;
import org.springframework.restdocs.RestDocumentationExtension;
import org.springframework.restdocs.mockmvc.*;
import org.springframework.restdocs.operation.preprocess.Preprocessors;
import org.springframework.test.context.junit.jupiter.SpringExtension;
import org.springframework.test.web.servlet.MockMvc;

@AutoConfigureRestDocs(uriScheme = "http", uriHost = "localhost", uriPort = 8080) // build폴더에 adoc파일 생성
@AutoConfigureMockMvc
@ExtendWith({SpringExtension.class, RestDocumentationExtension.class})
public abstract class MyRestDoc {
    @Autowired
    protected MockMvc mvc;
    protected RestDocumentationResultHandler document;

    @BeforeEach 
    public void documentSetUp() {
        this.document = MockMvcRestDocumentation.document("{class-name}/{method-name}",
                Preprocessors.preprocessRequest(Preprocessors.prettyPrint()),
                Preprocessors.preprocessResponse(Preprocessors.prettyPrint()));
    }
}
```

# 1.2 인증 테스트 - 회원가입 성공

다음과 같이 AuthControllerTest 클래스를 작성합니다. AuthControllerTest 클래스는 MyRestDoc을 구현해, 실제 서버를 구동하지 않고 MockMvc 환경에서 인증 API를 테스트할 수 있습니다.

> **@SpringBootTest은 Controller, Service, Repository 등 스프링의 모든 빈(Bean)을 로드하여 애플리케이션 전체를 테스트할 수 있도록 합니다. 이를 통해 실제 서버를 실행하지 않아도 스프링 컨텍스트 내에서 빈을 주입받아 테스트를 수행할 수 있습니다.**
> 

**controller/AuthControllerTest.java**


그리고 AuthControllerTest에 join_success_test 메서드를 작성합니다. 

> **테스트는 given, when, then 순으로 검증합니다. given은 테스트에 필요한 데이터를 준비 단계, when은 테스트 대상인 메서드나 API 호출을 하는 실행 단계, then은 실행 결과를 예측 데이터와 비교 검증하는 단계입니다.**
> 

then 단계에서는 응답 Body 데이터로 예상되는 값을 넣어, 요청 결과가 예상한대로 동작하는지를 테스트합니다 . 

**controller/AuthControllerTest.java**

```java
@Test
public void join_success_test() throws Exception {
        // given
        AuthRequest.JoinDTO joinDTO = new AuthRequest.JoinDTO("test", "1234", "test@nate.com");
        String requestBody = om.writeValueAsString(joinDTO);

        **// when
        ResultActions result = mvc.perform(
                        MockMvcRequestBuilders.post("/join")
                                        .contentType(MediaType.APPLICATION_JSON)
                                        .content(requestBody));
        // then
        result.andExpect(status().isOk()) // HTTP 상태코드 200
                        .andExpect(jsonPath("$.msg").value("성공"))
                        .andExpect(jsonPath("$.body.id").value(3))
                        .andExpect(jsonPath("$.body.username").value("test"))
                        .andExpect(jsonPath("$.body.email").value("test@nate.com"))
                        .andExpect(jsonPath("$.body.roles").value("USER"))
                        .andDo(MockMvcResultHandlers.print()).andDo(document);
}

```

# 1.3 인증 테스트 - 회원가입 실패

<aside>
💡

**통합 테스트는 시스템이 정상적으로 동작하는지 확인할 뿐만 아니라, 신뢰성과 안정성을 보장하기 위해 실패 케이스도 함께 검증해야 합니다. 예외 상황이 발생하더라도 시스템이 예상한 방식으로 처리되는지 확인하는 것이 중요하기 때문 입니다.**

**다만, 우리는 통합 테스트 연습 단계이므로 모든 실패 케이스를 다루기보다는, 회원가입 실패 케이스 한 가지만 작성하도록 하겠습니다.**

</aside>

AuthControllerTest에 join_fail_test 메서드를 작성합니다. 이메일 형식으로 입력하지 않은 경우를 테스트합니다. 

**controller/AuthControllerTest.java**

```java
@Test
public void join_fail_test() throws Exception {
        // given
        AuthRequest.JoinDTO joinDTO = new AuthRequest.JoinDTO("test", "1234", "test");
        String requestBody = om.writeValueAsString(joinDTO);

        // when
        ResultActions result = mvc.perform(
                        MockMvcRequestBuilders.post("/join")
                                        .contentType(MediaType.APPLICATION_JSON)
                                        .content(requestBody));
        // then
        result.andExpect(status().isBadRequest()) // HTTP 400
                        .andExpect(jsonPath("$.msg").value("email:이메일 형식이 올바르지 않습니다"))
                        .andExpect(jsonPath("$.body").isEmpty())
                        .andDo(MockMvcResultHandlers.print()).andDo(document);
}
```

# 1.4 유저네임 중복 체크 성공

checkUsername_success_test 메서드를 작성합니다. username에 test 값을 가진 사용자가 없기 때문에 true 값을 반환하게 됩니다.

**controller/AuthControllerTest.java**

```java
@Test
public void checkUsername_success_test() throws Exception {
        // given
        String username = "test";
        // when
        ResultActions result = mvc.perform(
                        MockMvcRequestBuilders.get("/check-username")
                                        .param("username", username));
        // then
        result.andExpect(status().isOk()) // HTTP 200
                        .andExpect(jsonPath("$.msg").value("성공"))
                        .andExpect(jsonPath("$.body.available").value(true))
                        .andDo(MockMvcResultHandlers.print()).andDo(document);
}
```
