# 6. API 문서 만들기

# 6.1 API 문서란?

> **API 문서는 다른 개발자가 서버에서 제공하는 API을 올바르게 사용할 수 있도록 정리한 안내서입니다. 요청 URL, HTTP 메서드, 입력 매개변수, 응답 데이터 구조 등 API 호출에 필요한 모든 정보를 설명합니다.**
> 

API 문서는 서버와 클라이언트가 어떤 방식으로 데이터를 주고받는지 알려주는 안내서입니다. 

개발자들은 이를 통해 필요한 요청과 응답 방식을 쉽게 이해하고 협업할 수 있습니다.

즉, API 문서는 서로 다른 시스템이 문제없이 연결되도록 도와주는 중요한 자료입니다.

<aside>
💡

**만약 API 문서 내용 중에 매개변수나, 응답 데이터, 요청 메서드 등 정보가 실제와 일치하지 않는다면 어떻게 될까요? API 요청을 보낸 다른 개발자는 이유를 알 수 없는 오류를 겪게 될 것입니다.**

**API 문서를 직접 작성하면 오타가 생기기 쉽고, 기능이 변경될 때마다 문서를 일일이 수정해야 하는 번거로움이 있습니다.**

</aside>

이를 해결하기 위해 우리는 Spring REST Docs를 활용해 API 문서를 자동으로 생성하는 방법을 알아보겠습니다.

> **Spring REST Docs는 테스트 코드의 결과를 이용해 자동으로 API 문서를 만들어주는 도구입니다.**
> 

Spring REST Docs 사용하기 위해선 build.gradle에 다음과 같은 의존성이 추가되어 있어야 합니다.

**build.gradle**

```jsx
testImplementation 'org.springframework.restdocs:spring-restdocs-mockmvc'
```

# 6.2 스니펫 파일 생성

> **스니펫(snippet)은 '작은 조각'을 의미하며, Spring REST Docs가 테스트 결과를 기반으로 자동 생성하는 API 문서 조각입니다.**
> 

API 문서는 실제 테스트를 통해 검증된 결과를 기반으로 자동 생성합니다.

MyRestDoc 클래스의 documentSetUp 메서드는 스니펫 파일의 저장 경로를 설정합니다.
테스트가 실행되면 스니펫은 **클래스명/메서드명** 형태의 폴더 구조로 생성됩니다.

# 6.3 자동화 설정

API 문서 자동화를 위해 build.gradle에 다음 설정을 추가합니다. 이 설정은 스프링 프로젝트를 실행 가능한 형태로 빌드할 때 자동으로 동작합니다.

**build.gradle**

```jsx
// 1. asciidoctor-restdocs를 위한 스니펫 디렉토리 경로를 정의합니다.
ext {
    set('snippetsDir', file("build/generated-snippets"))
}

// 2. 'test' 태스크가 실행되면 테스트 결과를 기반으로 API 문서 스니펫 파일을 생성합니다.
tasks.named('test') {
    outputs.dir snippetsDir
    useJUnitPlatform()
}

// 3. 'asciidoctor' 태스크는 테스트에서 생성된 스니펫(.adoc) 파일을 입력으로 받아서 최종적인 HTML API 문서로 변환합니다.
tasks.named('asciidoctor') {
    inputs.dir snippetsDir
	
    dependsOn test
}

// 4. 변환된 API 문서를 Spring Boot 프로젝트의 정적 리소스 디렉토리로 복사하는 태스크
tasks.register('copyRestDocs', Copy) {
    dependsOn tasks.named('asciidoctor')
    from "${asciidoctor.outputDir}"  // asciidoctor 결과 위치
    into "src/main/resources/static/docs"
}

tasks.named('bootJar') {
    dependsOn tasks.named('copyRestDocs')
}

// 5. 빌드시 plain jar 파일 생성하지 않기
jar {
    enabled = false
}
```

터미널창에 빌드 명령어를 실행합니다.

```jsx
./gradlew build
```

![**3.png**](6%20API%20%EB%AC%B8%EC%84%9C%20%EB%A7%8C%EB%93%A4%EA%B8%B0/image%202.png)

**3.png**

명령어가 성공적으로 실행되면, 스프링 프로젝트의 build 폴더 아래에 generated-snippets 폴더가 생성됩니다.
이 폴더 안에는 테스트 메서드의 이름 별로 구분된 폴더가 만들어지며, 각 폴더에는 .adoc 확장자의 스니펫 파일들이 저장됩니다.

**springv2 > build > generated-snippets**

# 6.4 API 문서 만들기 - 회원가입

generated-snippets 폴더 내부에 생성된 스니펫 파일을 모아서 API 문서를 만들어보겠습니다.

다음 그림처럼 docs/asciidoc 폴더에 **api.adoc** 파일을 생성합니다.

**src > docs > asciidoc > api.adoc**

![**5.png**](6%20API%20%EB%AC%B8%EC%84%9C%20%EB%A7%8C%EB%93%A4%EA%B8%B0/image%204.png)

**5.png**

api.adoc를 다음과 같이 회원가입 API 문서를 작성합니다. 이때, 스니펫 파일로는 **http-request.adoc**과 **http-response.adoc**을 포함합니다.

**docs/asciidoc/api.adoc**

```jsx
= SpringV2 API 문서
:toc: left  
:toclevels: 3
:source-highlighter: highlightjs

:snippets: ./build/generated-snippets
:auth: auth-controller-test
:user: user-controller-test
:board: board-controller-test
:reply: reply-controller-test
:admin: admin-controller-test

=== 1.Auth API
==== 1.1 회원가입

===== POST /join

새로운 사용자를 등록합니다.

include::{snippets}/{auth}/join_success_test/http-request.adoc[]
include::{snippets}/{auth}/join_success_test/http-response.adoc[]

===== POST /join (실패)

잘못된 이메일 형식으로 회원가입을 시도합니다.

include::{snippets}/{auth}/join_fail_test/http-request.adoc[]
include::{snippets}/{auth}/join_fail_test/http-response.adoc[]
```

작성 후 다시 빌드 명령어를 실행합니다.

```jsx
./gradlew build
```

명령어가 실행되면 다음 경로에 api.html 파일이 생성됩니다. 

> **생성된 api.html 파일은 build.gradle에 추가한 설정에 의해 api.adoc 파일이 HTML 형식으로 변환되어 복사된 결과물입니다.**
> 

**src > main >resources > static > docs**

# 6.5 API 문서 만들기 - 바이브 코딩으로 완성

API 문서를 완성하기 위해 다음과 같이 프롬프트를 작성합니다.

> **역할 : 너는 스프링 개발자야**
**맥락 : 지금 docs/asciidoc/api.adoc 파일에 API 문서를 작성 중이야**
**지시 사항 : generated-snippets 에 있는 adoc 파일을 사용해서 api.adoc 작성해줘
제약 : generated-snippets의 모든 테스트 결과 작성,  http-request.adoc와 http-response.adoc만 사용하면 돼
결과 형식 : api.adoc의 1.1 회원가입과 동일한 형태로 작성해줘**
> 

바이브 코딩으로 API 문서가 완성되었습니다.
