## 3.1.1  **application-dev.properties 설정**

프로젝트에 필요한 설정을 하겠습니다.

우선 서버의 포트와 인코딩 설정을 합니다.

**application-dev.properties**

```java
server.port=8080
spring.servlet.encoding.charset=UTF-8
spring.servlet.encoding.enabled=true
spring.servlet.encoding.force=true
```

그리고 데이터베이스 설정을 합니다.  개발용 데이터베이스로 H2 데이터베이스를 사용합니다. 

H2의 메모리 모드를 사용하면 데이터를 파일에 저장하지 않고 메모리 상에서만 빠르게 사용할 수 있습니다.

**application-dev.properties**

```java
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.url=jdbc:h2:mem:test // 메모리 모드 
spring.datasource.username=sa
spring.datasource.password=
spring.h2.console.enabled=true
```

다음으로 프로젝트 실행 시 초기 데이터의 경로와 테이블-데이터 간 생성 순서를 설정합니다. 

**application-dev.properties**

```java
spring.sql.init.data-locations=classpath:db/data.sql // 경로 설정
spring.jpa.defer-datasource-initialization=true // 테이블 생성-> 데이터 생성 순서 
```

그리고 JPA 와 관련된 설정을 합니다. JPA는 자바 객체와 데이터베이스 테이블을 자동으로 매핑시켜주는 역할을 합니다.

**application-dev.properties**

```java
spring.jpa.hibernate.ddl-auto=create // 프로젝트 실행 시 CREATE 명령어 새로 실행
spring.jpa.show-sql=true // SQL문 콘솔창에 출력
spring.jpa.properties.hibernate.format_sql=true // SQL 가독성 좋게 포맷
spring.jpa.open-in-view=false // 클라이언트 응답 전 데이터베이스 커넥션 종료
```

## 3.1.2 **application-prod.properties 설정**

**application-prod.properties**에서는 H2 대신 MySQL을 사용하고, 스키마 자동 생성은 비활성화(**ddl-auto=none**)합니다. CORS 허용 출처는 환경 변수로 전달된 도메인과 포트로 제한합니다.

**application-prod.properties**

```java
# ===== Server =====
server.port=8080
spring.servlet.encoding.charset=UTF-8
spring.servlet.encoding.enabled=true
spring.servlet.encoding.force=true

# ===== MySQL Datasource =====
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.datasource.url=jdbc:mysql://${RDS_HOSTNAME}:${RDS_PORT}/${RDS_DB_NAME}
spring.datasource.username=${RDS_USERNAME}
spring.datasource.password=${RDS_PASSWORD}

# ===== H2 console (사용 안 함) =====
spring.h2.console.enabled=false

# ===== JPA / Hibernate =====
spring.jpa.hibernate.ddl-auto=none
spring.jpa.open-in-view=false

# ===== Logging Level =====
logging.level.com.metacoding.springv2=INFO // 로그는 INFO 레벨

# ===== CORS Allow =====
app.cors.allowed-origins=http://${FRONTEND_HOSTNAME}:${FRONTEND_PORT}
```

# 3.2 데이터베이스 설계

## 3.2.1 user 엔티티

다음과 같이 User.java 클래스를 작성합니다.

**user/User.java**

```java
package com.metacoding.springv2.user;

import jakarta.persistence.*;
import lombok.*;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.userdetails.*;
import java.util.*;
import java.sql.Timestamp;
import org.hibernate.annotations.CreationTimestamp;

@NoArgsConstructor
@Getter
@Entity
@Table(name = "user_tb")
public class User implements UserDetails {

    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Id
    private Integer id;
    @Column(unique = true, length = 20, nullable = false)
    private String username;
    @Column(length = 60, nullable = false)
    private String password;
    @Column(length = 30, nullable = false)
    private String email;
    private String roles = "USER"; // 디폴트값은 USER

    @CreationTimestamp
    private Timestamp createdAt;

    @Builder
    public User(Integer id, String username, String password, String email, String roles, Timestamp createdAt) {
        this.id = id;
        this.username = username;
        this.password = password;
        this.email = email;
        this.roles = roles;
        this.createdAt = createdAt;
    }

    public void update(String email, String password) {
        this.email = email;
        this.password = password;
    }

    public void updateRoles(String roles) {
        this.roles = roles;
    }

    // 스프링 시큐리티 권한 처리
    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        Collection<GrantedAuthority> authorities = new ArrayList<>();
        // roles는 단일값 USER 혹은 복수값 USER,ADMIN 형태로 존재함
        String[] roleList = roles.split(",");

        for (String role : roleList) {
            authorities.add(() -> "ROLE_" + role);
        }
        return authorities;
    }
}
```

우리는 스프링 시큐리티를 활용해 인증, 권한 처리를 할 것입니다.

사용자가 로그인 요청을 보내면, 스프링 시큐리티는 아이디와 비밀번호를 검증하는 과정을 거칩니다.

> **인증이 성공하면, 스프링 시큐리티는 로그인한 사용자 정보를 Authentication 객체에 담아 보관합니다. 이때 Authentication 안에 들어가는 사용자 정보의 타입이 바로 UserDetails입니다.**
> 
> 
> **그래서 우리 애플리케이션에서 정의한 User 엔티티를 스프링 시큐리티가 사용할 수 있도록UserDetails 인터페이스를 구현해야 합니다.**
> 

UserDetails 를 구현하면 필수로 구현해야 하는 메서드가 **getUsername()**, **getPassword()**, **getAuthorities()** 입니다.

먼저 getUsername()과 getPassword() 메서드는 사용자 인증 체크에 사용됩니다.

> **getUsername()과 getPassword() 메서드는 각각 username, password 필드의 값을 반환해야 합니다. 해당 필드에 Lombok의 @Getter를 적용하면 자동으로 getter 메서드가 생성되므로, 별도로 구현하지 않아도 UserDetails 요구사항을 충족할 수 있습니다.**
> 

그리고 getAuthorities() 는 사용자의 권한 체크에 사용됩니다.

> **getAuthorities() 메서드는 사용자가 가진 역할 정보를 스프링 시큐리티가 이해할 수 있도록 변환하는 역할을 합니다.  역할 앞에 ROLE_ 접두사를 붙여 반환함으로써, 시큐리티가 권한을 올바르게 해석하고 인가 검증 과정에서 활용할 수 있도록 합니다.**
> 

## 3.2.2 board 엔티티

다음과 같이 Board.java 클래스를 작성합니다.

Board 엔티티는 @ManyToOne을 사용하여 회원(User)과의 관계를 설정합니다.

> **@ManyToOne 은 스프링에서 엔티티 간 N(다수):1 관계를 표현할 때 사용되는 외래키(FK)이며, 항상 다수 쪽 엔티티에 위치합니다. @ManyToOne를 통해 게시글에서 회원 정보를 참조할 수 있습니다.**
> 

**board/Board.java**

```java
package com.metacoding.springv2.board;

import java.sql.Timestamp;
import org.hibernate.annotations.CreationTimestamp;
import com.metacoding.springv2.user.User;
import jakarta.persistence.*;
import lombok.*;

@NoArgsConstructor
@Getter
@Entity
@Table(name = "board_tb")
public class Board {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;
    @Column(length = 30, nullable = false)
    private String title;
    @Column(length = 300, nullable = false)
    private String content;

    @ManyToOne(fetch = FetchType.LAZY)
    private User user;

    @CreationTimestamp
    private Timestamp createdAt;

    public void update(String title, String content) {
        this.title = title;
        this.content = content;
    }

    @Builder
    public Board(Integer id, String title, String content, User user, Timestamp createdAt) {
        this.id = id;
        this.title = title;
        this.content = content;
        this.user = user;
        this.createdAt = createdAt;
    }
}
```

## 3.2.3 reply 엔티티

Reply.java 클래스를 작성합니다.

Reply 엔티티에서는 @ManyToOne을 사용하여 댓글(Reply)에서 회원(User)과 게시글(Board)을 참조할 수 있도록 합니다.

**reply/Reply.java**

```java
package com.metacoding.springv2.reply;

import java.sql.Timestamp;
import org.hibernate.annotations.CreationTimestamp;
import com.metacoding.springv2.board.Board;
import com.metacoding.springv2.user.User;
import jakarta.persistence.*;
import lombok.*;

@NoArgsConstructor
@Getter
@Entity
@Table(name = "reply_tb")
public class Reply {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;
    @Column(length = 100, nullable = false)
    private String comment;

    @ManyToOne(fetch = FetchType.LAZY)
    private User user;

    @ManyToOne(fetch = FetchType.LAZY)
    private Board board;

    @CreationTimestamp
    private Timestamp createdAt;

    @Builder
    public Reply(Integer id, String comment, User user, Board board, Timestamp createdAt) {
        this.id = id;
        this.comment = comment;
        this.user = user;
        this.board = board;
        this.createdAt = createdAt;
    }

}
```

Reply 엔티티가 완성되면 Board 엔티티에 **replies 필드**를 추가합니다. replies 필드는 @OneToMany로 설정합니다.

> **@OneToMany는 N:1 관계에서 1쪽 엔티티에 선언됩니다. 즉, 게시글 엔티티에서 댓글을 참조할 수 있도록 합니다. 
단, 실제로는 단순한 참조 관계일 뿐 게시글 테이블에 별도 컬럼이 생성되지는 않습니다.**
> 

**Board.java**

```java
import java.util.*;
import com.metacoding.springv2.reply.Reply;

public class Board {
		// 생략...
		
    @OneToMany(mappedBy = "board", fetch = FetchType.LAZY, cascade = CascadeType.REMOVE)
    private List<Reply> replies = new ArrayList<>();
}
```
