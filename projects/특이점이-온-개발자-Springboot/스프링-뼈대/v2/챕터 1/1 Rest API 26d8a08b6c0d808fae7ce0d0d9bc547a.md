# 1. Rest API

> **REST API(Representational State Transfer API)는 REST 원칙을 기반으로 서버와 클라이언트가 데이터를 주고받는 방식입니다. 
즉, 클라이언트는 URI로 자원을 식별하고, HTTP 메서드(GET, POST, PUT, DELETE)를 활용해 해당 자원에 대한 요청과 응답을 처리합니다.**
>

# 1.2 JWT (JSON Web Token)

## 1.2.1 JSON(JavaScript Object Notation)

> **JSON은 데이터를 저장하고 교환하기 위한 데이터 포맷으로, 용량이 작고 가독성이 높습니다. 
언어나 플랫폼에 구애받지 않고 활용할 수 있어 현대의 웹과 API에서 표준처럼 널리 사용되고 있습니다.**
> 

JSON은 키-값 형태로, 다음과 같이 표현할 수 있습니다.

```java
{
  "id": 1,
  "username": "ssar",
  "email":"ssar@metacoding.com"
}
```

## 1.2.2 JWT

> **JWT는 JSON 기반의 토큰으로, 서버와 클라이언트가 인증과 권한 부여를 안전하게 처리할 수 있게 해주는 방식입니다.**
> 

토큰 인증 방식은 다음과 같습니다.

클라이언트가 서버에 인증을 요청해 성공하면, 서버는 토큰을 발급하여 클라이언트에 전달하고, 클라이언트는 이 토큰을 자신의 디바이스에 저장합니다.

![**4.png**](1%20Rest%20API/image%203.png)

**4.png**

로그인 이후 클라이언트는 요청 시 발급받은 토큰을 함께 전달하며, 서버는 해당 토큰을 검증한 뒤 유효할 경우 요청에 응답합니다.

![**5.png**](1%20Rest%20API/image%204.png)

**5.png**

일반 토큰은 단순 문자열로 되어 있어 검증을 위해 서버에 토큰 정보를 저장해야 합니다. 

반면 JWT는 토큰 안에 사용자 정보 등 인증과 관련된 정보가 저장되어 있기 때문에 서버는 사용자 정보를 저장하지 않고, 토큰 안의 정보만 확인하면 됩니다. 이를 통해 Stateless 상태를 만들 수 있습니다.

<aside>
💡

**Stateless 상태에서는 서버가 클라이언트 상태를 저장하지 않아 서버의 부하가 줄고, 서버 간 독립성이 생겨 서버를 쉽게 확장할 수 있습니다.** 

</aside>

다음 그림처럼, 로드밸런서를 통해 클라이언트의 요청을 여러 대의 서버로 처리하고 있습니다.

클라이언트 상태를 서버가 유지하는 **Stateful 상태**에서는 인증 정보가 특정 서버에 종속되기 때문에, 해당 서버만 요청을 정상적으로 처리할 수 있습니다. 
이때 로드 밸런서가 부하 분산을 위해 다른 서버로 요청을 전달하면, 해당 서버에는 인증 정보가 없으므로 요청이 실패하게 됩니다.

![**6.png**](1%20Rest%20API/image%205.png)

**6.png**

반면 **Stateless 방식**에서는 서버가 클라이언트로부터 전달받은 **JWT만 검증**하면 되므로, 로드 밸런서가 어떤 서버로 요청을 전달하더라도 동일하게 인증이 처리되어 정상적인 응답을 받을 수 있습니다.

# 1.3 Rest API 설계 규칙

> **요청할 자원은 URI에, 행위는 메서드로 표현합니다.**
> 

## 1.3.1 소문자 사용

URI에 포함된 영어는 소문자를 사용해서 작성합니다.

```html
⭕ /boards
```

```html
❌ /Boards
```

## 1.3.2 HTTP 메서드 사용

URI에는 행위를 포함하지 않으며, HTTP 메서드를 사용합니다. 

> **조회는 GET, 등록은 POST, 수정은 PUT, 삭제는 DELETE 메서드를 사용합니다.**
> 

```html
⭕ put요청 /boards/1
```

```java
❌ put요청 /boards/1/put
```

## 1.3.3 복수형 사용

요청할 자원은 단수형이 아닌 복수형을 사용합니다.

```html
⭕ /boards/1
```

```java
❌ /board/1
```

## 1.3.4 하이픈(-) 사용

긴 단어는 하이픈(-)을 활용해 구분합니다.

```html
⭕ /check-username
```

```java
❌ /check_username
```

## 1.3.5 확장자는 포함하지 않는다.

URI에는 확장자를 포함하지 않습니다. 대신 Header에 타입을 포함합니다. 

```html
⭕ /users    Header(application/json)
```

```java
❌ /users.json
```
