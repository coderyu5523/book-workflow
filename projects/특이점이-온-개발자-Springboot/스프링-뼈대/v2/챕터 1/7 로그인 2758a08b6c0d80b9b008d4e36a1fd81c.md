# 7. 로그인

# 7.1 AuthRequest

AuthRequest 클래스에 사용자명과 비밀번호를 입력받는 LoginDTO를 작성합니다.

**auth/AuthRequest.java**

```java
public record LoginDTO(
        @NotEmpty(message = "유저네임을 입력해주세요") String username,
        @NotBlank(message = "비밀번호를 입력해주세요") String password) {
}
```

# 7.2 UserService

LoginDTO로 전달받은 사용자 입력을 UserService에서 처리합니다. 로그인 메서드를 생성 후, DB에서 조회한 결과와 사용자 입력 값이 일치하면 JWT를 생성해 반환합니다.

**user/UserService.java**

```java
public String 로그인(AuthRequest.LoginDTO requestDTO) {
    User findUser = userRepository.findByUsername(requestDTO.username())
            .orElseThrow(() -> new Exception404("유저네임 혹은 비밀번호가 일치하지 않습니다"));
    if (!bCryptPasswordEncoder.matches(requestDTO.password(), findUser.getPassword()))
        throw new Exception401("유저네임 혹은 비밀번호가 일치하지 않습니다");
    return JwtUtil.create(findUser);
}
```

<aside>
💡

**비밀번호는 BCrypt로 암호화될 때마다 내부적으로 무작위 Salt가 추가되므로, 단순 문자열 만으로 비교할  수 없습니다. 대신 BCryptPasswordEncoder의 matches 메서드를 사용해야 합니다. BCrypt 해시 문자열에는 사용된 Salt와 반복 횟수 정보가 함께 저장되므로, 이를 기반으로 사용자가 입력한 비밀번호를 동일한 방식으로 해시해 결과를 비교할 수 있습니다.**

</aside>

BCrypt 해시 값에서 버전과 비용 정보를 제외한 다음 22자리가 Salt입니다. 로그인 시에는 이 Salt 정보를 활용해 사용자가 입력한 비밀번호를 동일한 방식으로 해시한 뒤 비교합니다.

# 7.3 AuthController

컨트롤러에서는 /login 요청이 들어오면 사용자 데이터를 서비스 계층에 전달하고, 인증이 성공하면 결과를 응답으로 반환합니다.

**auth/AuthController.java**

```java
@PostMapping("/login")
public ResponseEntity<?> login(@Valid @RequestBody AuthRequest.LoginDTO requestDTO, Errors errors) {
    var responseDTO = userService.로그인(requestDTO);
    return Resp.ok(responseDTO);
}
```
