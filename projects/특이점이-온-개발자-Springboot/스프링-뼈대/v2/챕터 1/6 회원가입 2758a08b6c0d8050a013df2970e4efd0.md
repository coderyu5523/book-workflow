# 6. 회원가입

우리는 지금까지 프로젝트의 파일 구조 세팅과 설정을 마쳤습니다. 이제부터는 프로젝트의 기능을 하나씩 구현해 보겠습니다.

# 6.1 UserRepository

> **Repository는 스프링에서 데이터베이스와 상호작용을 하는 계층입니다.**
> 

UserRepository는 JpaRepository 인터페이스를 상속받아 구현합니다.

JpaRepository는 엔티티에 대한 기본 CRUD 기능을 자동으로 제공하며, 메서드 이름 규칙등을 활용해 비교적 복잡한 조회 쿼리도 간단히 구현할 수 있습니다.

**user/UserRepository.java**

```java
package com.metacoding.springv2.user;

import org.springframework.data.jpa.repository.JpaRepository;
import java.util.Optional;

public interface UserRepository extends JpaRepository<User, Integer> {
    Optional<User> findByUsername(String username); 
}
```

findByUsername 메서드는 전달된 username 값을 기준으로 JPA가 자동으로 SELECT 쿼리를 생성해 실행합니다.

# 6.2 DTO

> **DTO(Data Transfer Object) 계층 간 데이터 전달을 위해 사용하는 객체입니다. 요청 데이터는 Request, 응답은 Response 파일에 작성합니다.**
> 

 ****

AuthRequest 클래스에는 사용자가 입력한 회원가입 정보를 담을 JoinDTO를 정의합니다.
이때, @Size, @NotBlank 등 Bean Validation 어노테이션을 사용해 각 필드의 값이 지정된 조건을 만족하는지 자동으로 검증합니다.

<aside>
💡

**DTO 클래스는 record 타입으로 정의할 수 있습니다. record는 생성자, 접근자(getter) 등 메서드를 자동으로 생성하며, 모든 필드를 불변으로 유지해 DTO를 안전하고 간단하게 표현할 수 있습니다.**

</aside>

**auth/AuthRequest.java**

```java
package com.metacoding.springv2.auth;

import com.metacoding.springv2.user.User;
import jakarta.validation.constraints.*;

public class AuthRequest {
    public record JoinDTO(
            @Size(min = 4, max = 20, message = "유저네임은 4자 이상 20자 이하로 입력해주세요") @NotEmpty(message = "유저네임을 입력해주세요") String username,
            @NotBlank(message = "비밀번호를 입력해주세요") @Size(min = 4, max = 60, message = "비밀번호는 4~60자여야 합니다") String password,
            @Email(message = "이메일 형식이 올바르지 않습니다") String email) {
        public User toEntity(String encPassword) {
            return User.builder()
                    .username(username)
                    .password(encPassword)
                    .email(email)
                    .roles("USER")
                    .build();
        }
    }
}
```

그리고 인증 완료 후 응답받을 데이터를 받을 공통 DTO 클래스를 AuthResponse 클래스에 생성합니다. 

**auth/AuthRequest.java**

```java
package com.metacoding.springv2.auth;

import com.metacoding.springv2.user.User;

public class AuthResponse {
    public record DTO(Integer id, String username, String email, String roles) {
        public DTO(User user) {
            this(user.getId(), user.getUsername(), user.getEmail(), user.getRoles());
        }
    }
}
```

<aside>
💡

**DTO는 인증이 완료된 User 객체를 응답할 때 사용되며, 보안을 위해 비밀번호와 같은 민감한 정보는 반드시 제외해야 합니다.**

</aside>

# 6.3 UserService

> **Service 계층은 데이터베이스와 상호작용하는 레파지토리와 요청을 받는 컨트롤러 사이에 위치하며, 비지니스 로직을 담당하는 계층입니다.**
> 

다음과 같이 UserService를 작성합니다.

@Service로 스프링 컨테이너에 등록하고, @RequiredArgsConstructor와 final 키워드를 사용해 UserRepository를 주입받습니다.

**user/UserService.java**

```java
package com.metacoding.springv2.user;

import java.util.*;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import com.metacoding.springv2.auth.*;
import com.metacoding.springv2.core.handler.ex.*;
import com.metacoding.springv2.core.util.JwtUtil;
import lombok.RequiredArgsConstructor;

@Transactional(readOnly = true) // 변경감지 생략
@RequiredArgsConstructor
@Service
public class UserService {

    private final UserRepository userRepository;
    private final BCryptPasswordEncoder bCryptPasswordEncoder; // 비밀번호 암호화
    
    // 메서드 작성

}
```

이제 UserService 클래스에 회원가입 메서드를 작성하겠습니다.

JoinDTO의 toEntity 메서드를 활용해 사용자 입력 데이터를 user 엔티티로 변환합니다. 그리고 JpaRepository에서 제공하는 save 메서드를 이용해 데이터를 저장합니다.

이때 비밀번호는 BCrypt 해시 함수를 통해 암호화한 후 생성해야 보안을 강화할 수 있습니다.

> **JpaRepository는 데이터베이스와 매핑된 엔티티를 대상으로 동작하므로, 사용자가 입력한 데이터를 그대로 저장할 수는 없습니다. 따라서 JoinDTO의 toEntity 메서드를 사용해 DTO를 User 엔티티로 변환한 뒤 저장합니다.**
> 

**user/UserService.java**

```java
@Transactional
public AuthResponse.DTO 회원가입(AuthRequest.JoinDTO requestDTO) {
    if (userRepository.findByUsername(requestDTO.username()).isPresent())
        throw new Exception401("이미 존재하는 유저네임입니다");
    String encPassword = bCryptPasswordEncoder.encode(requestDTO.password());
    User savedUser = userRepository.save(requestDTO.toEntity(encPassword));
    return new AuthResponse.DTO(savedUser);
}
```

# 6.4 AuthController

> **컨트롤러 계층은 클라이언트의 요청을 받아 서비스 계층으로 전달하고, 응답을 클라이언트에게 돌려주는 역할을 합니다.**
> 

AuthController에 다음과 같이 작성합니다.

컨트롤러에 **@RestController**를 적용하면 응답이 자동으로 HTTP Response Body 형태로 전달되므로, 결과를 Resp의 Body에 담아 클라이언트에 보낼 수 있습니다.

> **@Valid는 DTO에 선언된 유효성 검증 어노테이션을 검사하며, 검증 결과는 Errors 객체에 담깁니다. 컨트롤러에서는 이 정보를 활용해 예외 상황을 처리할 수 있습니다.**
> 

**auth/AuthController.java**

```java
package com.metacoding.springv2.auth;

import org.springframework.http.ResponseEntity;
import org.springframework.validation.Errors;
import org.springframework.web.bind.annotation.*;
import com.metacoding.springv2.core.util.Resp;
import com.metacoding.springv2.user.UserService;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;

@RequiredArgsConstructor
@RestController
public class AuthController {

    private final UserService userService;

    @PostMapping("/join")
    public ResponseEntity<?> join(@Valid @RequestBody AuthRequest.JoinDTO requestDTO, Errors errors) {
        var responseDTO = userService.회원가입(requestDTO);
        return Resp.ok(responseDTO);
    }
}
```

<aside>
💡

**HTTP 메서드 중 POST와 PUT 요청은 반드시 변경된 데이터를 응답 본문(Body)에 포함해야 합니다. 그래야 클라이언트가 서버와 추가 통신 없이 저장 또는 수정된 최신 상태를 즉시 반영할 수 있으며, 사용자 경험을 높일 수 있습니다.**

</aside>
