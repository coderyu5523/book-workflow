# 2.1 **DB 환경 설정**

> **application.properties는 스프링 프로젝트의 환경 설정 값을 모아두는 파일입니다. 여기서 서버 포트, DB 연결 정보, 로그 설정 등 애플리케이션 실행에 필요한 기본 환경을 설정할 수 있습니다.**
> 

application.properties는 src 폴더의 resources 폴더에 있습니다.

**src > main > resources > application.properties**

>

```java

spring.datasource.url=jdbc:h2:mem:test
spring.h2.console.enabled=true
spring.datasource.username=sa
spring.datasource.password=
```

# 2.2  **Board 엔티티 생성**

> **엔티티(Entity)는 데이터베이스 테이블과 1:1로 매핑되는 자바 클래스입니다. JPA에서 @Entity 어노테이션을 사용하면 해당 클래스가 자동으로 테이블과 연결되어, 자바 객체를 테이블처럼 조회·저장·수정할 수 있습니다.**
> 

엔티티 생성 전에 application.properties에 아래와 같이 설정을 해줍니다. 아래 설정은 스프링 실행 시 @Entity 어노테이션이 붙은 클래스를 테이블로 자동으로 생성시키며, 실행되는 SQL 을 콘솔창에서 확인할 수 있습니다.

**application.properties**

```sql
spring.jpa.hibernate.ddl-auto=create
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

<aside>
💡

**단, ddl-auto=create 설정은 스프링 실행 시 매번 테이블을 생성하기 때문에 개발 단계에서만 사용해야 하며, 실제 운영 시에는 절대 사용하면 안됩니다.**

</aside>

board 폴더에 Board.java 파일을 생성합니다. 이 파일은 데이터베이스의 게시글 테이블과 매핑될 객체입니다.

**scr > main > java > com > metacoding > springv1 > board**

**3.png**

아래와 같이 Board 파일을 구성해줍니다.

> **@Table 어노테이션은 데이터베이스의 어떤 테이블과 매핑될지 지정하는 기능이며,
@Data 어노테이션은 클래스의 필드 값을 조회·변경할 수 있는 Getter, Setter 메서드를 자동으로 만들어주는 기능입니다.**
> 

**board/Board.java**

```java
package com.metacoding.springv1.board;

import jakarta.persistence.*;
import lombok.Data;

@Data // 속성값 
@Entity // 매핑될 클래스 지정
@Table(name="board_tb") // 매핑될 클래스명은 board_tb
public class Board {
    
}
```

이제 테이블의 컬럼 값을 만들겠습니다. 컬럼은 데이터베이스의 컬럼과 동일해야 합니다.

컬럼은 고유번호, 제목, 내용, 생성시간으로 구성되어 있습니다.

> **여기서 id는 테이블의 기본 키(Primary Key)로, 각 행을 구분하는 유일한 값이며 @GeneratedValue 어노테이션을 사용해 데이터 저장 시 값이 자동 증가되도록 설정했습니다.**
> 

**board/Board.java**

```java
package com.metacoding.springv1.board;

import java.sql.Timestamp;

import org.hibernate.annotations.CreationTimestamp;

import jakarta.persistence.*;
import lombok.*;

@Data
@Entity  
@Table(name="board_tb") 
public class Board {
    @Id
    @GeneratedValue (strategy = GenerationType.IDENTITY)  // 자동 증가
    private Integer id;
    private String title;
    private String content;

    @CreationTimestamp // 자동으로 현재 시간 저장
    private Timestamp createdAt;
}

```

테이블을 생성했으니 다음으로 데이터를 입력해보겠습니다.

# 2.3 **더미 데이터 구축**

> **더미 데이터는 개발이나 테스트 과정에서 사용하는 실제 데이터가 아닌 가상의 데이터를 의미합니다.**
> 
> 
> **주로 기능 검증이나 화면 테스트를 위해 임시로 생성됩니다.**
> 

데이터 생성 전 application.properties 에서 몇 가지 설정을 하겠습니다. 

아래의 설정은 스프링 실행 시 데이터가 로드될 때에 관한 설정입니다. 

**application.properties**

```java
spring.sql.init.data-locations=classpath:db/data.sql // 더미 데이터 접근 경로
spring.jpa.defer-datasource-initialization=true // 테이블 생성 -> SQL 순 지정
```

<aside>
💡

**defer-datasource-initialization=true 설정은 스프링이 테이블 생성 작업을 마친 뒤 SQL 스크립트를 실행하도록 지정합니다. 이 설정이 없으면 SQL이 테이블 생성보다 먼저 실행되어 테이블이 없다는 오류가 발생할 수 있습니다.**

</aside>
