# 4. 게시글 목록보기

# 4.1 **서비스 계층 (findAll)**

> **스프링의 서비스(Service) 계층은 컨트롤러와 레포지토리 사이에서 애플리케이션의 비즈니스 로직을 수행하는 핵심 영역입니다. 컨트롤러로부터 요청과 데이터를 전달받아 필요한 연산이나 규칙을 적용하고, 레포지토리를 호출해 데이터 저장·조회 작업을 수행합니다.**
> 
> 
> **서비스 계층을 두면 요청 처리(컨트롤러)와 데이터 접근(레포지토리)의 책임이 분리되어, 구조가 명확하고 유지보수가 쉬워집니다.**
>

다음의 코드처럼 BoardService 를 작성해줍니다. 

> **@Service 어노테이션을 통해 해당 클래스를 컴포넌트 스캔의 대상이자 스프링 관리 빈(Bean)으로 등록합니다.**
> 

의존성 주입(Dependancy Injection) 시 생성자 주입 방식을 적용하기 위해 @RequiredArgsConstructor와  final 필드 패턴을 사용합니다.

**BoardService.java**

```java
package com.metacoding.springv1.board;

import org.springframework.stereotype.Service;

import lombok.RequiredArgsConstructor;

@RequiredArgsConstructor
@Service
public class BoardService {

    private final BoardRepository boardRepository;
    
    // 메서드 작성
}
```

<aside>
💡

**@RequiredArgsConstructor 와 final을 함께 사용하면 생성자 주입을 자동으로 구현하면서 주입된 의존성을 불변으로 보장합니다. 이는 객체 생성 시 반드시 필요한 의존성을 강제해 null 인 객체를 참조할 때 발생하는 오류를 방지하고, 런타임 중 의존성 변경을 방지해 코드의 안정성과 유지보수성을 높입니다. 

따라서 우리는 @Autowired 보다 @RequiredArgsConstructor + final 패턴을 사용하도록 하겠습니다.**

</aside>

BoardService에 게시글목록() 메서드를 생성합니다. BoardRepository의 findAll() 메서드를 통해 전체 데이터를 조회합니다.

**BoardService.java**

```java
public List<Board> 게시글목록() {
    List<Board> boards = boardRepository.findAll();
    return boards;
}
```

# 4.2 **컨트롤러 계층 (findAll)**

> **컨트롤러 계층은 클라이언트의 요청을 수신하고, 요청에 맞는 서비스 계층의 로직을 호출하여 처리 결과를 반환하는 역할을 합니다.**
> 
> 
> **비즈니스 로직을 직접 구현하지 않고, 요청 데이터 매핑·검증과 응답 형식 변환을 담당하며, 뷰 렌더링이나 API 응답 생성을 통해 최종 결과를 클라이언트에 제공합니다.**
> 

BoardController 에 구현한 index() 메서드에 코드를 추가합니다. 그리고 BoardService를 DI(의존성 주입)을 합니다.

**BoardController.java**

```java
@RequiredArgsConstructor
@Controller
public class BoardController {

    private final BoardService boardService;

    @GetMapping("/")
    public String index() {
        List<Board> boards = boardService.게시글목록();
        return "index";
    }
    
    // 생략
}
```

# 4.4 Request 담기

> **index() 메서드의 매개변수로 전달된 HttpServletRequest 객체는 컨트롤러에서 생성한 데이터를 뷰로 전달하는 역할을 합니다. request.setAttribute("키", 값) 형태로 데이터를 저장하면, 뷰에서 해당 키를 사용해 값을 출력하거나 바인딩할 수 있습니다.**
> 

**BoardController.java**

```java
package com.metacoding.springv1.board;

import java.util.List;
import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.*;
import jakarta.servlet.http.HttpServletRequest;
import lombok.RequiredArgsConstructor;

@RequiredArgsConstructor
@Controller
public class BoardController {

    private final BoardService boardService;
    
    @GetMapping("/")
    public String index(HttpServletRequest request) {
        List<Board> boards = boardService.게시글목록();
        request.setAttribute("models", boards);
        return "index";
    }
    
    // 중략
}
```

<aside>
💡

**request객체는 application.properties에 지정한 설정 옵션에 따라 Mustache 템플릿에서 직접 참조할 수 있습니다. 또한, 스프링에서 제공하는 Model 객체를 활용하여 템플릿에 데이터를 전달하는 방식도 사용할 수 있습니다.**

</aside>

**application.properties**

```java
spring.mustache.servlet.expose-request-attributes=true
```

# 4.5 **Mustache로 출력**

templates > board 폴더 내부의 index.mustache로 이동합니다. 

> **Mustache 문법 중 데이터가 List 타입인 경우, {{#켈렉션}} … {{/컬렉션}} 구문을 사용하여 각 요소를 순회하며 반복문처럼 렌더링할 수 있습니다.**
> 

**index.mustache**

```jsx
{{> header}} 
<div class="container mt-3">
  <table class="table table-hover">
    <thead>
      <tr>
        <th>번호</th>
        <th>제목</th>
        <th>내용</th>
      </tr>
    </thead>
    <tbody>
		{{#models}}
		  <tr onclick="location.href='/boards/{{id}}'" style="cursor: pointer;">
		    <td>
		        {{id}}
		    </td>
		    <td>
		        {{title}}
		    </td>
		    <td>
		        {{content}}
		    </td>
		  </tr>
		{{/models}}
    </tbody>
  </table>
</div>
</body>
</html>
```

> **컬렉션 내부에서 데이터 바인딩은 {{변수}} 구문을 사용하여 템플릿에 값을 출력합니다.**
> 

```sql
{{#컬렉션}}
{{id}  {{title}} {{content}}
{{/컬렉션}}
```
