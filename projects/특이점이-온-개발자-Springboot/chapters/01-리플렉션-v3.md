# 챕터 1. 리플렉션

오픈이는 이제 막 개발을 배우기 시작한 학생입니다. 이번 학기 과제는 게시판 웹 서버를 만들어 제출하는 것입니다. 써 본 언어가 자바(Java)뿐이라 자바로 코드를 쓰기 시작했지만, 몇 줄 쓰기도 전에 벽에 부딪혔습니다.

문제는 게시판 기능이 아니라 그 이전 단계에 있었습니다. 브라우저와 연결을 맺으려면 소켓부터 직접 열어야만 했습니다. 연결이 된 후에는 요청 문자열을 잘라내어 어떤 주소를 요청했는지 파악해야 했고, 그 주소마다 실행할 코드를 일일이 연결해 주어야 했습니다.

게시글 화면 하나 만들지 못했는데 통신과 문자열 처리에만 수십 줄이 쌓였습니다. 오픈이는 모니터를 보며 한숨을 쉬었습니다.

*과제는 게시판인데, 서버 뼈대만 만들다 학기가 끝나겠네.*

다음 날, 같은 수업을 듣는 선배에게 사정을 털어놓았습니다. 화면을 훑어보던 선배가 말했습니다.

**선배**: "이런 기본 뼈대를 밑바닥부터 직접 짜는 사람은 없어요. 프레임워크를 사용하면 통신 연결이나 주소 분배 같은 공통 기능은 이미 갖춰져 있거든요. 자바 웹이면 보통 스프링을 쓰니까, 그 위에 만들고 싶은 게시판 기능만 구현해 봐요."

## 1.1 스프링의 실행 원리

### 1.1.1 라이브러리와 프레임워크

날짜를 계산하거나 파일을 읽을 때처럼, 개발자가 필요할 때마다 직접 꺼내 쓰는 도구를 **라이브러리(Library)** 라고 합니다. 언제 어떤 기능을 쓸지, 프로그램의 전체 흐름은 개발자가 정합니다.

반면, 스프링과 같은 **프레임워크(Framework)** 는 다릅니다. 통신 연결이나 주소 분배처럼 웹 서버가 갖춰야 할 기본 뼈대가 이미 완성되어 있습니다. 건축으로 치면 기둥과 벽, 배관 공사까지 모두 끝난 상태와 같습니다. 개발자는 바닥부터 새로 집을 짓는 대신, 미리 세워진 뼈대 안에서 자신이 원하는 기능만 채워 넣으면 됩니다.

## 1.2 리플렉션 구현

리플렉션이 실제로 어떻게 동작하는지 자바 코드로 직접 구현해 보겠습니다. 가장 단순한 형태의 코드부터 시작해 한 단계씩 기능을 확장해 나갑니다.

### 1.2.1 if-else 라우팅

가장 원시적인 요청 처리 방식은 요청 주소를 `if` 문으로 비교해 알맞은 메서드를 직접 호출하는 것입니다. 먼저 게시글을 다루는 `BoardController`에 등록(insert), 삭제(delete), 수정(update) 세 메서드를 작성합니다. 각 메서드는 호출되면 콘솔에 이름을 찍습니다.

`ex01/BoardController.java`를 열고 아래 코드를 작성합니다.

```java [실습 1] ex01/BoardController.java. 요청을 처리할 컨트롤러
public class BoardController {

    public void insert() {
        System.out.println("insert 호출됨");
    }

    public void delete() {
        System.out.println("delete 호출됨");
    }

    public void update() {
        System.out.println("update 호출됨");
    }
}
```

이제 이 컨트롤러를 호출하는 `main` 메서드를 작성합니다. `uri`에 담긴 요청 주소를 담당 메서드로 넘기는 연결 작업을 라우팅(Routing)이라고 합니다.

`ex01/App.java`를 열고 아래 코드를 작성합니다.

```java [실습 2] ex01/App.java. 주소에 따라 메서드 호출
public class App {
    public static void main(String[] args) {

        String uri = "/insert";
        BoardController boardController = new BoardController();

        // TODO: uri에 맞는 메서드를 직접 호출한다
        // 1. 주소가 /insert면 insert() 호출
        if (uri.equals("/insert")) {
            boardController.insert();
        // 2. /update면 update() 호출
        } else if (uri.equals("/update")) {
            boardController.update();
        // 3. /delete면 delete() 호출
        } else if (uri.equals("/delete")) {
            boardController.delete();
        }
    }
}
```

`uri`가 `/insert`이므로, 실행하면 콘솔에 `insert 호출됨`이 출력됩니다.

그래서 필요한 것이 리플렉션입니다. 호출부를 고치지 않고, 실행 중에 컨트롤러의 메서드를 살펴 알맞은 메서드를 찾아 호출하는 방식으로 바꿔 보겠습니다.

스프링에는 `@RequestMapping` 같은 어노테이션이 이미 준비되어 있습니다. 어떻게 동작하는지 이해하기 위해, 같은 이름의 어노테이션을 직접 만들어 보겠습니다.

`ex02/RequestMapping.java`를 열고 아래 코드를 작성합니다. `RequestMapping`은 메서드마다 담당할 요청 주소를 적어 두는 어노테이션입니다.

```java [실습 3] ex02/RequestMapping.java. 주소를 담는 커스텀 어노테이션
// 1. 실행 중(런타임)에도 이 어노테이션을 읽을 수 있게 유지한다
@Retention(RetentionPolicy.RUNTIME)
// 2. 메서드 위에만 붙일 수 있는 어노테이션으로 지정한다
@Target(ElementType.METHOD)
public @interface RequestMapping {
    // 3. 이 어노테이션이 담을 속성 - 담당할 주소
    String uri();
}
```

어노테이션은 클래스나 인터페이스처럼 `@interface` 키워드로 정의합니다. `RequestMapping`은 메서드에만 붙일 수 있고, 컴파일한 뒤에도 사라지지 않아 실행 중에 리플렉션이 읽을 수 있습니다.

이제 앞서 `if` 문으로 비교하던 주소를, 각 메서드의 어노테이션으로 옮깁니다. `ex02/BoardController.java`를 열고 아래처럼 메서드마다 `@RequestMapping`을 추가합니다.

```java [실습 4] ex02/BoardController.java. 메서드마다 담당 주소를 어노테이션으로
public class BoardController {

    @RequestMapping(uri = "/insert")
    public void insert() {
        System.out.println("insert 호출됨");
    }

    @RequestMapping(uri = "/delete")
    public void delete() {
        System.out.println("delete 호출됨");
    }

    @RequestMapping(uri = "/update")
    public void update() {
        System.out.println("update 호출됨");
    }

    @RequestMapping(uri = "/select")
    public void select() {
        System.out.println("select 호출됨");
    }
}
```

이제 `main` 메서드가 `if` 문 없이 이 어노테이션을 읽어 요청 주소와 맞는 메서드를 호출하면 됩니다.

`ex02/App.java`를 열고 아래 코드를 작성합니다.

```java [실습 5] ex02/App.java. 어노테이션을 읽어 맞는 메서드를 호출
public class App {
    public static void main(String[] args) {

        String uri = "/update";
        BoardController boardController = new BoardController();

        // TODO: 어노테이션을 읽어 uri가 일치하는 메서드를 실행한다
        // 1. 컨트롤러가 가진 모든 메서드를 꺼낸다
        Method[] methods = boardController.getClass().getDeclaredMethods();
        for (Method method : methods) {
            // 2. 그 메서드에 붙은 @RequestMapping 어노테이션을 읽는다
            RequestMapping rm = method.getDeclaredAnnotation(RequestMapping.class);
            // 3. 어노테이션의 uri가 요청 주소와 같으면 그 메서드를 실행한다
            if (rm.uri().equals(uri)) {
                try {
                    method.invoke(boardController);
                    break;
                } catch (Exception e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

`ex03/BoardController.java`를 열고 클래스 선언 위에 `@Controller`를 추가합니다.

```java [실습 7] ex03/BoardController.java. 클래스 위에 @Controller 어노테이션
@Controller
public class BoardController {

    @RequestMapping(uri = "/insert")
```

이제 핵심인 `main` 메서드입니다. `new BoardController()`는 어디에도 없습니다. 대신 `main` 메서드가 `ex03` 폴더의 실제 경로를 찾아, 폴더 안의 클래스 파일을 하나씩 확인해 `@Controller`가 붙은 것만 객체로 만듭니다.

```java [실습 8] ex03/App.java. 폴더를 뒤져 @Controller 클래스를 자동 등록
public class App {
    public static void main(String[] args) throws URISyntaxException,
            ClassNotFoundException, InstantiationException, IllegalAccessException {
        // TODO: ex03 폴더를 뒤져 @Controller 클래스만 객체로 만든다
        // 1. ex03 폴더의 실제 경로를 찾는다
        ClassLoader classLoader = Thread.currentThread().getContextClassLoader();
        URL packageUrl = classLoader.getResource("com/reflection/ex03");
        File ex03 = new File(packageUrl.toURI());

        List<Object> instances = new ArrayList<>();

        // 2. 폴더 안의 .class 파일을 하나씩 살핀다
        for (File file : ex03.listFiles()) {
            System.out.println("파일명: " + file.getName());
            if (file.getName().endsWith(".class")) {
                String className = "com.reflection.ex03." + file.getName().replace(".class", "");
                Class cls = Class.forName(className);
                // 3. @Controller 어노테이션이 붙은 클래스만 객체로 만들어 보관한다
                if (cls.isAnnotationPresent(Controller.class)) {
                    System.out.println("어노테이션이 있는 클래스 : " + file.getName());
                    Object instance = cls.newInstance();
                    instances.add(instance);
                }
            }
        }

        System.out.println("--------------------------------");

        // 4. 보관한 객체에서 주소에 맞는 메서드를 찾아 실행한다
        findUri(instances, "/delete");
    }
}
```

이번에는 객체가 여러 개일 수 있으므로, 보관한 객체를 하나씩 확인하는 코드를 `findUri` 메서드로 분리합니다.

```java [설명] ex03/App.java. 보관한 객체에서 주소로 메서드 찾기
public static void findUri(List<Object> instances, String uri) {
    for (Object instance : instances) {
        Method[] methods = instance.getClass().getDeclaredMethods();
        for (Method method : methods) {
            RequestMapping rm = method.getDeclaredAnnotation(RequestMapping.class);
            if (rm.uri().equals(uri)) {
                try {
                    method.invoke(instance);
                    break;
                } catch (Exception e) {
                    e.printStackTrace();
                }
            }
        }
    }
}
```

### 1.3.2 의존성 주입

그렇다면 이렇게 만들어진 빈은 어떻게 서로 기능을 주고받을까요? 한 객체가 다른 객체를 필요로 하는 상태를 '의존성을 가진다'고 표현합니다. 그런데 코드 내부에서 의존 객체를 직접 생성하면 객체 간의 결합도가 높아져 나중에 코드를 수정하거나 테스트하기가 까다로워집니다.

스프링은 이 문제를 **의존성 주입(Dependency Injection)** 이라는 방식으로 해결합니다. 빈이 다른 빈의 기능을 써야 할 때, 개발자는 필요한 빈을 직접 만들지 않고 무엇이 필요한지만 코드에 적어 둡니다. 그러면 컨테이너가 실행될 때 만들어 둔 빈 중에서 찾아 넣어 주고, 빈은 주입받은 빈의 메서드를 그대로 호출할 수 있습니다.

:::remember
**이것만은 기억하자**

- **프레임워크는 공통으로 필요한 뼈대를 미리 갖춘 틀입니다.** 개발자는 뼈대를 다시 만들지 않고, 갖춰진 틀 위에 자기 기능만 구현합니다.
- **개발자가 직접 호출하지 않아도, 스프링은 리플렉션으로 알맞은 메서드를 찾아 실행합니다.** 메서드에 붙은 어노테이션으로 호출할 대상을 찾고, 컴포넌트 스캔으로 클래스에 붙은 어노테이션을 찾아 객체를 등록합니다.
:::
