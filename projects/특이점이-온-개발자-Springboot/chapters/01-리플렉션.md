# 챕터 1. 리플렉션 - 스프링은 어떻게 내 코드를 실행하는가

오픈이는 개발을 배우는 학생입니다. 이번 학기 과제는 웹 서버를 만들어 제출하는 것입니다. 배운 것이 자바뿐이라 자바로 서버를 짜기 시작했지만, 몇 줄 쓰기도 전에 막혔습니다. 브라우저의 요청을 받으려면 통신 연결부터 열어야 했고, 주소를 꺼내려면 문자열을 한 글자씩 잘라 읽어야 했습니다. 주소마다 어떤 처리를 할지 일일이 연결하고, 응답 규격까지 직접 맞춰야 했습니다.

*과제는 게시판인데, 서버 뼈대만 만들다 학기가 끝나겠네.*

날짜 계산이나 파일 읽기처럼 필요할 때 꺼내 쓰는 기능을 라이브러리(Library)라고 합니다. 개발자가 직접 호출하고, 프로그램이 어떤 순서로 흐를지도 개발자가 정합니다.

## 1.2 리플렉션 - 이름을 몰라도 찾아 호출한다

주도권이 프레임워크로 넘어갔다는 것은, 개발자가 방금 작성한 코드를 스프링이 대신 실행해 준다는 뜻입니다. 그런데 스프링이 그 코드를 실행하는 일은 간단하지 않습니다.

보통의 자바 프로그램은 개발자가 `new`로 객체를 만들고, 이름을 정확히 적어야 메서드를 호출할 수 있습니다. 반면 스프링은 개발자가 앞으로 어떤 클래스를 만들고 그 안에 어떤 메서드를 둘지 미리 알 수 없습니다. 이름도 모르는 코드를, 실행 중에 찾아내 호출해야 합니다.

이 일을 가능하게 하는 기술이 **리플렉션(Reflection)** 입니다. 리플렉션은 프로그램이 실행되는 도중(런타임)에 클래스와 메서드, 필드 정보를 읽고 호출까지 할 수 있는 자바의 기능입니다.

## 1.3 if-else 라우팅과 그 한계

가장 원시적인 요청 처리 방식은 요청 주소를 `if` 문으로 비교해 알맞은 메서드를 직접 호출하는 것입니다. 예를 들어 `/insert`, `/update`, `/delete` 주소가 들어왔을 때 각각 컨트롤러의 알맞은 메서드를 호출하도록 분기문을 작성할 수 있습니다.

먼저 요청을 처리할 컨트롤러를 만듭니다. 게시글을 다루는 `BoardController`에 등록(insert), 삭제(delete), 수정(update) 세 메서드를 둡니다. 각 메서드는 자신이 호출되었다는 것을 콘솔에 찍기만 합니다.

`ex01/BoardController.java`를 열고 아래 코드를 작성합니다.

```java [실습 1] ex01/BoardController.java. 요청을 처리할 컨트롤러
public class BoardController {

    public void insert() {
        System.out.println("insert 호출됨");
    }

    public void delete() {
        System.out.println("delete 호출됨");
    }

    public void update() {
        System.out.println("update 호출됨");
    }
}
```

이제 이 컨트롤러를 호출하는 `main`을 작성합니다. `uri` 변수에 요청 주소가 담겨 있다고 가정하고, `main`이 그 값을 `if` 문으로 하나씩 비교해 알맞은 메서드로 연결합니다. 요청 주소를 받아 담당 메서드로 넘겨주는 이 연결 작업을 라우팅(Routing)이라고 합니다.

`ex01/App.java`를 열고 TODO 자리에 아래 코드를 작성합니다.

```java [실습 2] ex01/App.java. 주소에 따라 메서드 호출
public class App {
    public static void main(String[] args) {
        String uri = "/insert";
        BoardController boardController = new BoardController();

        // TODO: uri에 맞는 메서드를 직접 호출한다
        // 1. 주소가 /insert면 insert() 호출
        if (uri.equals("/insert")) {
            boardController.insert();
        // 2. /update면 update() 호출
        } else if (uri.equals("/update")) {
            boardController.update();
        // 3. /delete면 delete() 호출
        } else if (uri.equals("/delete")) {
            boardController.delete();
        }
    }
}
```

`uri` 값이 `/insert`이므로, `main`을 실행하면 첫 번째 조건이 맞아 `main`이 `insert()`를 호출합니다. 콘솔에 `insert 호출됨`이 출력됩니다.

여기까지는 잘 동작합니다. 그런데 게시글을 조회하는 기능이 필요해져, 컨트롤러에 `select` 메서드를 하나 더 추가한다고 해 보겠습니다.

```java [설명] ex01/BoardController.java. 메서드 추가
public void select() {
    System.out.println("select 호출됨");
}
```

메서드를 추가하는 것만으로는 끝나지 않습니다. `/select` 요청이 들어와도 `main`의 `if` 문에는 그 주소를 처리할 분기가 없기 때문입니다. 결국 개발자가 `App.java`로 돌아가 `else if (uri.equals("/select"))` 한 줄을 또 붙여야 합니다.

메서드를 하나 추가할 때마다 그것을 호출하는 `main`의 `if` 문까지 함께 고쳐야 한다는 것, 이것이 이 방식의 한계입니다.

그래서 필요한 것이 리플렉션입니다. 호출부를 건드리지 않고, 실행 중에 컨트롤러를 들여다보며 알맞은 메서드를 찾아 호출하는 방식으로 바꿔 보겠습니다.

## 1.4 리플렉션과 표식으로 찾아 호출

*그림 1-4. if문은 등록된 주소만 실행하지만, 리플렉션은 @표식을 읽어 처음 보는 주소도 실행합니다*

스프링에는 `@RequestMapping` 같은 어노테이션이 이미 준비되어 있습니다. 그 정체를 이해하기 위해, 같은 이름의 어노테이션을 직접 만들어 보겠습니다.

`ex02/RequestMapping.java`를 열고 아래 코드를 작성합니다. 어노테이션은 클래스나 인터페이스처럼 `@interface` 키워드로 정의합니다.

```java [실습 3] ex02/RequestMapping.java. 주소를 담는 커스텀 어노테이션
// 1. 실행 중(런타임)에도 이 표식을 읽을 수 있게 유지한다
@Retention(RetentionPolicy.RUNTIME)
// 2. 메서드 위에만 붙일 수 있는 표식으로 지정한다
@Target(ElementType.METHOD)
public @interface RequestMapping {
    // 3. 이 표식이 담을 속성 - 담당할 주소
    String uri();
}
```

이 어노테이션은 각 메서드에 담당 주소를 달아 두는 표식입니다. `String uri()`에 그 메서드가 맡을 주소를 적습니다.

이제 앞서 `if` 문으로 비교하던 주소를, 각 메서드의 표식으로 옮깁니다. `ex02/BoardController.java`를 열고 아래처럼 메서드마다 `@RequestMapping`을 답니다.

```java [실습 4] ex02/BoardController.java. 메서드마다 담당 주소를 표식으로
public class BoardController {

    @RequestMapping(uri = "/insert")
    public void insert() {
        System.out.println("insert 호출됨");
    }

    @RequestMapping(uri = "/delete")
    public void delete() {
        System.out.println("delete 호출됨");
    }

    @RequestMapping(uri = "/update")
    public void update() {
        System.out.println("update 호출됨");
    }

    @RequestMapping(uri = "/select")
    public void select() {
        System.out.println("select 호출됨");
    }
}
```

각 메서드가 자신이 담당할 주소를 명찰처럼 달고 있습니다. 이제 `main`이 `if` 문 없이, 이 명찰을 읽어 요청 주소와 맞는 메서드를 찾아 호출하면 됩니다.

`ex02/App.java`를 열고 TODO 자리에 아래 코드를 작성합니다.

```java [실습 5] ex02/App.java. 표식을 읽어 맞는 메서드를 호출
public class App {
    public static void main(String[] args) {
        String uri = "/update";
        BoardController boardController = new BoardController();

        // TODO: 표식을 읽어 uri가 일치하는 메서드를 실행한다
        // 1. 컨트롤러가 가진 모든 메서드를 꺼낸다
        Method[] methods = boardController.getClass().getDeclaredMethods();
        for (Method method : methods) {
            // 2. 그 메서드에 붙은 @RequestMapping 표식을 읽는다
            RequestMapping rm = method.getDeclaredAnnotation(RequestMapping.class);
            // 3. 표식의 uri가 요청 주소와 같으면 그 메서드를 실행한다
            if (rm.uri().equals(uri)) {
                method.invoke(boardController);
                break;
            }
        }
    }
}
```

`main`이 컨트롤러의 메서드를 모두 꺼낸 뒤, 표식에 적힌 주소가 요청 주소와 같은 메서드를 찾아 `invoke()`로 호출하는 흐름입니다. 개발자가 메서드 이름을 미리 알지 못해도, 리플렉션이 실행 중에 표식을 읽어 맞는 메서드를 호출합니다.

`uri`가 `/update`이므로, 리플렉션이 `/update` 표식을 단 `update()`를 호출합니다. 실행하면 콘솔에 `update 호출됨`이 출력됩니다.

그러면 컨트롤러에 새 메서드를 추가할 때는 어떻게 해야 할까요?

```java [설명] ex02/BoardController.java. 표식을 단 메서드만 추가
@RequestMapping(uri = "/create")
public void create() {
    System.out.println("create 호출됨");
}
```

컨트롤러에 표식을 단 메서드를 추가하는 것으로 끝입니다. `main`은 어떤 메서드가 새로 생겼는지 알 필요가 없습니다. 실행 중에 메서드 목록을 다시 훑어 표식을 읽을 뿐이므로, 호출부 코드는 한 글자도 건드리지 않습니다.

## 1.5 폴더를 뒤져 자동 등록·실행

한 가지가 아직 남았습니다. `main`은 여전히 `new BoardController()`로 컨트롤러를 직접 만들고 있습니다. 컨트롤러가 하나면 상관없지만, 게시판 컨트롤러, 회원 컨트롤러, 댓글 컨트롤러처럼 늘어나면 그때마다 개발자가 `new`를 손으로 적어야 합니다. 프레임워크는 개발자가 어떤 컨트롤러를 만들지 미리 알 수 없으므로, 이 방식도 결국 앞의 `if` 문과 같은 한계에 부딪힙니다.

그래서 이번에는 클래스를 직접 `new` 하지 않습니다. 프로그램이 지정한 폴더를 뒤져, 표식이 붙은 클래스만 골라 자동으로 객체로 만듭니다. 이 기능을 **컴포넌트 스캔(Component Scan)** 이라고 합니다.

*그림 1-5. 폴더 안의 클래스를 하나씩 살펴 표식이 붙은 것만 객체로 만들어 보관하고, 요청이 오면 그 객체에서 메서드를 찾아 실행합니다*

이번에는 메서드가 아니라 클래스에 붙일 표식이 필요합니다. 컨트롤러 역할을 하는 클래스라는 것을 나타내는 `@Controller` 어노테이션을 만듭니다.

`ex03/Controller.java`를 열고 아래 코드를 작성합니다. 메서드가 아닌 클래스에 붙이므로 `@Target`을 `ElementType.TYPE`으로 지정합니다.

```java [실습 6] ex03/Controller.java. 컨트롤러임을 나타내는 표식
@Retention(RetentionPolicy.RUNTIME)
// 1. 클래스나 인터페이스 위에 붙일 수 있는 표식으로 지정한다
@Target(ElementType.TYPE)
public @interface Controller {
}
```

앞서 만든 `RequestMapping.java`는 그대로 재사용합니다. `ex03` 폴더에도 같은 어노테이션이 필요하므로, `ex02`의 것을 복사해 둡니다. 이제 `BoardController` 클래스 위에 `@Controller`를 답니다. 이 표식이 붙은 클래스를 스캔으로 찾아내는 것이 목적입니다.

`ex03/BoardController.java`를 열고 클래스 선언 위에 `@Controller`를 추가합니다.

```java [실습 7] ex03/BoardController.java. 클래스 위에 @Controller 표식
@Controller
public class BoardController {

    @RequestMapping(uri = "/insert")
    public void insert() { System.out.println("insert 호출됨"); }

    @RequestMapping(uri = "/delete")
    public void delete() { System.out.println("delete 호출됨"); }

    @RequestMapping(uri = "/update")
    public void update() { System.out.println("update 호출됨"); }

    @RequestMapping(uri = "/select")
    public void select() { System.out.println("select 호출됨"); }

    @RequestMapping(uri = "/create")
    public void create() { System.out.println("create 호출됨"); }
}
```

이제 핵심인 `main`입니다. `new BoardController()`는 어디에도 없습니다. 대신 `main`이 `ex03` 폴더의 실제 경로를 찾아, 그 안의 클래스 파일을 하나씩 살피며 `@Controller`가 붙은 것만 객체로 만듭니다.

`ex03/App.java`를 열고 TODO 자리에 아래 코드를 작성합니다.

```java [실습 8] ex03/App.java. 폴더를 뒤져 @Controller 클래스를 자동 등록
public class App {
    public static void main(String[] args) {
        // TODO: ex03 폴더를 뒤져 @Controller 클래스만 객체로 만든다
        // 1. ex03 폴더의 실제 경로를 찾는다
        ClassLoader classLoader = Thread.currentThread().getContextClassLoader();
        URL packageUrl = classLoader.getResource("com/reflection/ex03");
        File ex03 = new File(packageUrl.toURI());

        List<Object> instances = new ArrayList<>();

        // 2. 폴더 안의 .class 파일을 하나씩 살핀다
        for (File file : ex03.listFiles()) {
            System.out.println("파일명: " + file.getName());
            if (file.getName().endsWith(".class")) {
                String className = "com.reflection.ex03." + file.getName().replace(".class", "");
                Class cls = Class.forName(className);
                // 3. @Controller 표식이 붙은 클래스만 객체로 만들어 보관한다
                if (cls.isAnnotationPresent(Controller.class)) {
                    Object instance = cls.newInstance();
                    instances.add(instance);
                }
            }
        }

        // 4. 보관한 객체에서 주소에 맞는 메서드를 찾아 실행한다
        findUri(instances, "/delete");
    }
}
```

`main`이 `ex03` 폴더를 뒤져, `.class` 파일 중 `@Controller`가 붙은 클래스만 골라 객체로 만들어 `instances`에 담는 흐름입니다. `new BoardController()`는 어디에도 없습니다.

찾아서 호출하는 뒷부분은 실습 5에서 만든 리플렉션 로직 그대로입니다. 이번에는 객체가 여러 개일 수 있으므로, 보관한 객체를 하나씩 훑도록 `findUri` 메서드로 감쌌습니다.

```java [설명] ex03/App.java. 보관한 객체에서 주소로 메서드 찾기
public static void findUri(List<Object> instances, String uri) {
    for (Object instance : instances) {
        Method[] methods = instance.getClass().getDeclaredMethods();
        for (Method method : methods) {
            RequestMapping rm = method.getDeclaredAnnotation(RequestMapping.class);
            if (rm.uri().equals(uri)) {
                method.invoke(instance);
                break;
            }
        }
    }
}
```

`main`을 실행하면 콘솔에 폴더 안 파일들의 이름이 하나씩 찍히고, `@Controller`가 붙은 `BoardController`만 객체로 등록됩니다. 마지막으로 `findUri`에 넘긴 `/delete` 주소에 맞는 메서드가 호출되어 `delete 호출됨`이 출력됩니다.

*그림 1-8. 요청이 톰캣과 디스패처 서블릿을 거쳐 컨트롤러 메서드로 전달되고, 서비스와 리포지토리를 지나 데이터베이스까지 이어지는 흐름입니다*

브라우저가 8080 포트로 요청을 보내면 웹 서버인 톰캣(Tomcat)이 받습니다. 톰캣은 요청의 헤더와 본문을 담은 `req` 객체와, 응답을 담을 `resp` 객체를 만들어 스프링으로 넘깁니다.

톰캣을 통과한 요청은 스프링 컨테이너의 진입점인 **디스패처 서블릿(DispatcherServlet)** 으로 넘어갑니다. 디스패처 서블릿은 앞서 `findUri`가 표식을 읽어 맞는 메서드를 호출했듯, 컴포넌트 스캔과 리플렉션으로 들어온 주소를 담당하는 컨트롤러 메서드를 찾아 호출합니다.

호출된 컨트롤러(C)는 요청에 따른 응답 처리를 담당하고, 핵심 비즈니스 로직은 서비스(S)로 넘깁니다. 서비스는 트랜잭션을 관리하며 리포지토리(R)를 통해 데이터베이스에 질의를 수행합니다. 이 과정에서 영속성 컨텍스트(PC)가 자바 객체와 데이터베이스 간의 데이터를 안전하게 관리합니다.
