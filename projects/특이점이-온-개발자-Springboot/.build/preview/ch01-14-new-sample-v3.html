1.4 Spring MVC

Spring MVC는 스프링에서 웹 요청을 처리하는 모듈입니다. 앞에서 main 메서드가 직접 하던 일, 즉 요청 주소에 맞는 메서드를 찾아 호출하는 일을 Spring MVC가 대신하고, 그 결과로 응답까지 만듭니다. Spring MVC의 이름과 구조는 MVC 패턴에서 왔습니다.

1.4.1 MVC 패턴

MVC 패턴은 웹 애플리케이션의 코드를 요청을 처리하는 컨트롤러(Controller), 처리 결과 데이터를 담는 모델(Model), 화면을 만드는 뷰(View) 로 나누는 설계 방식입니다. 컨트롤러가 요청을 처리해 결과를 모델에 담으면, 뷰는 모델의 데이터로 화면을 만들어 응답합니다.

그림 1-17. MVC 패턴

이렇게 역할을 나누면 화면을 바꿀 때는 뷰만 고치면 되고, 요청을 처리하는 컨트롤러는 그대로 둘 수 있습니다.

1.4.2 디스패처 서블릿

Spring MVC는 MVC 패턴의 세 역할 앞에 디스패처 서블릿(DispatcherServlet) 을 둡니다. 모든 요청은 디스패처 서블릿에 먼저 도착하고, 디스패처 서블릿은 요청 주소에 맞는 컨트롤러 메서드를 호출한 뒤, 컨트롤러가 모델을 반환하면 이를 뷰에 넘겨 응답을 만듭니다.

그림 1-18. Spring MVC의 구조

요청을 받아 세 역할을 연결하는 일은 디스패처 서블릿이 맡으므로, 개발자는 요청마다 실행할 코드를 컨트롤러에 작성하면 됩니다.

1.4.3 톰캣과 필터

디스패처 서블릿에 요청을 넘겨주는 것은 톰캣(Tomcat) 입니다. 톰캣은 자바 코드를 실행해 동적인 결과를 만들어 내는 웹 애플리케이션 서버(WAS) 로, 네트워크로 들어온 요청을 자바 객체로 바꿔 서블릿(Servlet) 에 넘깁니다. 서블릿은 톰캣으로부터 요청을 받아 처리하는 자바 객체이고, Spring MVC는 디스패처 서블릿을 서블릿으로 톰캣에 등록해 모든 요청을 받습니다.

그림 1-19. 디스패처 서블릿에 요청을 넘기는 톰캣

요청은 디스패처 서블릿에 도착하기 전에 톰캣 안에서 필터(Filter) 를 먼저 거칩니다. 필터는 인증이나 인코딩처럼 모든 요청에 공통으로 필요한 작업을 처리하며, Spring MVC보다 앞에서 동작합니다.
