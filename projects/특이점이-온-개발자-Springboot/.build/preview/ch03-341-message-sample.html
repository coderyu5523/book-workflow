3.4.1 예외 처리 흐름 — 시안 (A안)

실패 사유가 예외에 담기는 곳(그림 3-4 ②) → 꺼내는 곳(그림 3-5 e.getMessage()) → 응답(JSON msg)이 이어지게 맞춘 시안입니다. 용어는 챕터 전체가 쓰는 "실패 사유"로 통일했습니다. 주황 밑줄이 바뀐 부분입니다.

시안

3.4.1 예외 처리 흐름

요청을 처리하는 도중 컨트롤러나 서비스에서 문제가 생기면 실패 사유를 담은 예외가 발생합니다. 이 예외를 그 자리에서 처리하지 않으면, 아래 그림처럼 호출된 순서를 거꾸로 거쳐 디스패처 서블릿까지 전달됩니다.

그림 3-4. 게시글을 찾지 못해 발생한 예외의 전달

디스패처 서블릿까지 전달된 예외는 전역 예외 처리기로 넘어갑니다. 전역 예외 처리기(Global Exception Handler) 는 모든 컨트롤러에서 발생한 예외를 한곳에서 처리하는 클래스입니다. 예외를 그대로 두면 클라이언트는 사유 없이 500 오류만 받으므로, 전역 예외 처리기에서 예외를 상태 코드와 실패 사유를 담은 응답으로 바꿉니다.

그림 3-5. 전역 예외 처리기의 응답

이 응답은 디스패처 서블릿을 거쳐 클라이언트에게 전달됩니다.

바뀐 곳 정리

1. 본문 첫 단락: 호출 순서 설명·예시 문장 삭제. 일반 흐름 두 문장 — 어디서든 발생(컨트롤러나 서비스) + 실패 사유를 담음 + 그 자리에서 처리하지 않으면 거꾸로 거쳐 디스패처까지. 예시는 "아래 그림처럼"으로 그림에 넘김
2. 그림 3-4: ② 배지 아래 점선 상자 "Exception404 / 실패 사유: 게시글을 찾을 수 없습니다" 추가 (서비스 코드 new Exception404("게시글을 찾을 수 없습니다")와 같은 값)
3. 그림 3-4 캡션: "예외 발생과 전달" → "게시글을 찾지 못해 발생한 예외의 전달" (예시 상황은 캡션이 맡음)
4. 셋째 단락: 원문 그대로 ("상태 코드와 실패 사유를 담은 응답")
5. 그림 3-5: "예외 메시지" → "실패 사유" (챕터 용어와 통일), JSON을 status → msg → body 순서로 (그림 3-7 실제 응답과 같음)
