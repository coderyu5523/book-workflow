1.4 스프링의 요청 흐름

요청이 서버에 도착해 컨트롤러에 전달되고, 응답이 클라이언트에 돌아가기까지의 과정을 단계별로 살펴보겠습니다.

클라이언트의 요청이 서버에 도착했을 때 가장 먼저 이를 맞이하는 것은 톰캣(Tomcat) 입니다. 톰캣은 자바 코드를 실행해 동적인 웹 페이지나 데이터를 만들어 내는 웹 애플리케이션 서버(WAS) 입니다. 톰캣은 클라이언트가 보낸 HTTP 요청 메시지를 읽고, 이를 자바 프로그램이 다룰 수 있도록 요청 객체로 변환합니다. 동시에 앞으로 생성될 결과를 담아둘 비어 있는 응답 객체도 함께 준비합니다.

그림 1-17. 톰캣의 요청 객체 생성

톰캣은 요청 처리에 앞서 필터(Filter) 를 차례대로 실행합니다. 필터는 이름 그대로 요청을 걸러내고 가공하는 역할을 하며, 한글 깨짐을 방지하는 인코딩 처리나 사용자의 권한을 검사하는 인증 확인처럼 여러 요청에 공통으로 필요한 사전 작업을 담당합니다.

그림 1-18. 필터의 공통 처리

필터 체인을 통과한 요청은 스프링의 영역인 디스패처 서블릿(DispatcherServlet) 에 도착합니다. 스프링은 서버가 구동될 때 컴포넌트 스캔으로 컨트롤러를 빈으로 등록하고, 리플렉션을 활용해 매핑 목록을 만들어 둡니다. 디스패처 서블릿은 이 목록을 확인하여 현재 들어온 요청 주소에 알맞은 컨트롤러의 메서드를 찾아내고, 이를 리플렉션으로 호출합니다.

그림 1-19. 디스패처 서블릿의 메서드 호출

컨트롤러가 맡은 작업을 마치고 결과를 반환하면, 디스패처 서블릿은 이 데이터를 처음에 톰캣이 만들어둔 응답 객체에 담아줍니다. 응답 객체는 들어왔던 길을 되돌아가 필터를 거꾸로 거친 뒤 톰캣에게 돌아갑니다. 마지막으로 톰캣이 이 응답 객체를 클라이언트가 이해할 수 있는 HTTP 응답 메시지로 변환하여 전송하면 하나의 요청 처리가 끝납니다.

1.5 학습 지도 그림은 1-18에서 1-20으로 번호가 밀립니다.

지금 원고의 1.4 (비교용)

요청이 서버에 도착해서 컨트롤러에 전달되기까지 어떤 단계를 거치는지 따라가 보겠습니다.

(그림 1-17. 요청 처리 흐름: 톰캣 안에 필터와 스프링(디스패처 서블릿 → 컨트롤러)을 한 장에 그린 그림)

1. 톰캣과 필터. 톰캣(Tomcat)은 자바 코드를 실행해 동적인 결과를 만들어 내는 웹 애플리케이션 서버(WAS) 입니다. 클라이언트가 보낸 통신 요청을 스프링이 이해할 수 있는 객체로 변환해 전달하고, 스프링이 만든 최종 결과를 다시 응답하는 출입문 역할을 합니다. 요청은 스프링으로 넘어가기 전에 먼저 필터(Filter)를 거치는데, 필터에서는 인증이나 인코딩처럼 애플리케이션 전반에 공통으로 필요한 작업을 미리 걸러내어 처리합니다.

2. 디스패처 서블릿. 필터를 무사히 통과한 요청은 디스패처 서블릿(DispatcherServlet) 으로 들어옵니다. 디스패처 서블릿은 스프링으로 들어오는 모든 요청을 맨 앞에서 가로챈 뒤, 요청 주소(URL)를 분석하여 이를 담당할 가장 적절한 컨트롤러를 찾아 길을 안내해 줍니다.

3. 컨트롤러 호출. 디스패처 서블릿은 찾아낸 컨트롤러의 메서드를 리플렉션으로 호출합니다. 컨트롤러가 반환한 결과는 요청이 지나온 경로를 거꾸로 거쳐 클라이언트에 전달됩니다.
