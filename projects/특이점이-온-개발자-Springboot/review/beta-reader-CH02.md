## 심각도별 이슈

### 높음 (기술 정확성 / 실습 무효화)
- **IDENTITY 전략 ↔ 쓰기지연 충돌** (DBA·시니어 둘 다): 예제 엔티티가 `@GeneratedValue(IDENTITY)`라 `persist` 시 INSERT가 **즉시** 실행됨(생성 키를 받아야 영속 관리 가능). 그런데 그림 2-6/본문은 "INSERT를 버퍼에 모았다 flush에 낸다"고 가르침 → **show-sql을 켜면 로그가 그림과 정면 충돌**. 쓰기지연은 UPDATE/DELETE엔 유효하니, 예시를 더티체킹으로 들거나 "IDENTITY는 예외" 한 줄 명시 필요.
- **2.9 `./gradlew test` → eye용 `println` 출력이 CLI에 안 보임** (CS학생): `build.gradle`에 `testLogging.showStandardStreams` 없음. "Board title : title-update"를 눈으로 확인하는 절 전체 payoff가 CLI에선 사라짐. IDE 실행 안내 또는 gradle 설정 필요.

### 중간
- **실습4 컨트롤러가 실습5의 `BoardRequest.SaveDTO`를 먼저 참조** → 순서대로 채우다 중간 컴파일 시 미정의 심볼 에러 (Java신입·Node). 정의 순서 재배치 또는 안내.
- **테스트 5개 중 `update_test` 하나만 본문 공개**하고 "전체 테스트 실행"을 지시 → 나머지 4개 출처 불명으로 초보가 막힘 (부트캠프·others).
- 2.7 실행 안내에 전체 URL(`http://localhost:8080/...`)·POST/PUT/DELETE 도구(curl·Postman) 없음 (CS학생).
- EntityManager 직접 사용이 실무 표준 `JpaRepository`와 다른데 예고 한 줄 없음 (CTO).
- CH02가 책 내 **최대 개념 밀도**(REST+ORM+3계층+영속성3종+트랜잭션+테스트) → 학습곡선 급경사, 완급·분할 검토 (CTO·부트캠프).
- `ResponseEntity<?>` 와일드카드 무설명 반복 (부트캠프).

### 기술 정확성 (감수)
- **L494 "세 가지 모두 flush 시점에 반영됩니다"** (시니어): 캐싱(1차 캐시)은 읽기 최적화라 flush로 DB에 '반영'되는 대상이 아님. flush에서 SQL이 나가는 건 쓰기지연·더티체킹뿐. → **v2 압축 문장**, 아래 참조.
- **"바뀐 부분만 UPDATE로 내보냅니다"** (시니어): 기본 Hibernate는 변경 '여부'만 감지, SET 절엔 전체 컬럼(`@DynamicUpdate` 미사용 시). "바뀐 부분만"은 부정확. → **v2 압축 문장**.
- 도입 훅 약함/2.3~2.9 중반 캐릭터 부재 (CTO·시니어·others).

### 낮음
- `@Data` on JPA 엔티티 안티패턴(향후 연관관계에서 문제) — CTO.
- 완성 코드 `jakarta.transaction.Transactional` (스프링 표준 아님, readOnly 불가) — Node·시니어.
- `defer-datasource-initialization` 없으면 부팅 실패 위험(아래 v2 컷 참조).
