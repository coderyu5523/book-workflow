## 심각도별 이슈

### 높음 (데이터 페르소나 / 실습 재현 불가)
- **ER/스키마 다이어그램 부재** (DBA): `user_tb(id PK, username UNIQUE, password, email)` ↔ `board_tb(... user_id FK)` 관계 그림이 하나도 없음. 비유 그림 6칸에 데이터 구조 0칸. 애노테이션→실제 DDL(FK·UNIQUE) 다리가 SQL 능숙자에게 안 놓임.
- **로그인 테스트용 평문 비밀번호가 본문에 없음** (DBA): `data.sql`은 `ssar`/`cos`를 BCrypt 해시로만 심음 → 구축 파트로 `POST /login`을 눌러 401→200→403 흐름을 직접 재현하려면 시드 계정 평문을 알아야 하는데 안 알려줌.

### 중간
- 회원가입 401 / 로그인 404·401 계정 열거 (위 공통, 7명).
- BoardController 코드 공백 (위 공통, 4명).
- 호수 비유 미회수 (위 공통, 6명).
- Spring Security 미언급 (위 공통, 시니어·CTO).
- **필터/인터셉터 2단의 기술적 필연성(서블릿 컨테이너 레벨 vs Spring MVC 레벨·경로패턴) 미설명** — "관심사 분리"로만 정당화 (Node·Python·CS).
- **무상태 장점 편향** — Stateless를 확장성 이점 위주로만, JWT 폐기 불가 트레이드오프(로그아웃·탈취 토큰 만료 전 무효화 불가) 누락 (시니어·CS).
- 요청 전송 도구(Postman/curl) 안내 부재 — 4.1 첫 실습 (CS·부트캠프).
- DB unique 제약 + 앱 중복 체크 역할 구분 없음 (DBA).
- 실습 파일 6개 다 채울 때까지 중간 검증 지점 없음 → 오타 역추적 어려움 (Java신입).
- 4.1 20행 클래스표 + 파일 트리 동시 등장(압도) + 실습 총 개수 미고지 (부트캠프). CTO: 그림 4-1 오버뷰를 4.2 뒤로.

### 감수 정확성 (낮음~중하, 시니어)
- **"POST는 몸통에 실어 위험을 줄인다"(L474)** — 전송 보호는 TLS이지 POST가 아님. "POST=안전" 오독 소지 (시니어·CTO).
- 그림 4-5 헤더 "HMAC512" — 실제 JWT alg 값은 `HS512`(HMAC512는 auth0 메서드명).
- `verify`가 서명만 강조 — `JWT.require().verify()`는 만료(exp)도 자동 검증. 어디서 만료 처리되는지 안 드러남.
- BCrypt salt·cost 미짚음 → "되돌릴 수 없다"면서 `matches` 대조되는 원리가 모순처럼 보임.
- SECRET 짧은 하드코딩 + 시크릿 관리 무언급.
- `resolveToken`의 `replace(TOKEN_PREFIX,"")` — `substring`이 정석(코드 스멜).

### 경미
- `SESSION_USER` 상수 선언 후 미사용(문자열 직접) — 3명.
- `(User) request.getAttribute(...)` 캐스팅 이유(Object 반환) 미설명 — 부트캠프.
- Exception401/403 "먼저 만듭니다"(4.9) vs 파일트리 [참고](미리 제공) 충돌 — Node·부트캠프.
- data.sql 시드 해시 cost 04 vs PasswordEncoder cost 10 (동작하나 무주석).
- 클라(OkHttp) 인터셉터 vs 서버 인터셉터 방향 반대 안내 부재 — Android.
