## 심각도별 이슈

### 중간
- **"나머지 메서드도 같은 식으로" (L223)** — v2에서 내가 압축한 문장. 목록 반환의 `stream().map(::new).toList()` 메서드 레퍼런스 패턴이 챕터 어디에도 안 나와, 부트캠프 초보는 "높음" 블로커로 지적. → **코드 한 줄 복원 검토.**
- **Board `@Builder` 누락** — 파일트리(L106~115)·클래스표(L85~93)에 `Board.java`가 없는데 L193이 "@Builder를 더합니다"라고만 함. 트리대로 작업하면 컴파일 에러. Board는 `@NoArgsConstructor`+명시 생성자 위에 `@Builder`가 붙는 형태라 "클래스에 붙일지 생성자에 붙일지"도 초보가 모름.
- **@ExceptionHandler 두 갈래** (시니어·DBA·Java신입·CTO):
  - (a) `Exception404` 핸들러와 `Exception.class` catch-all이 둘 다 매칭되는데 왜 404가 500에 안 먹히나(스프링이 가장 구체적 핸들러 선택) — 설명 부재.
  - (b) catch-all 500이 스프링 내장 4xx(`MethodArgumentTypeMismatch`=잘못된 경로 타입, `HttpMessageNotReadable`=깨진 JSON)까지 500으로 뭉갬 → "catch-all 500이 안전"이라는 얕은 오개념. 한 줄 단서 권장.
- **삭제 void vs "삭제도 DTO 받는다" (L236)** — 코드는 `게시글삭제`가 void → `Resp.ok(null)`. 본문 "작성·수정·삭제도 똑같이 DTO를 받습니다"와 불일치 (Java신입).
- **createdAt 프레이밍 약함** (DBA·CTO) — 구멍2(엔티티 노출)의 현재 피해가 `createdAt` 하나뿐인데, createdAt은 상세에서 오히려 **보여주고 싶은** 값. 실제 민감 필드(password·userId)는 CH04라 CH03 시점 동기가 추상적. 구멍1(404)이 즉시 체감되어 강한 것과 비대칭. → 구멍2를 "지금은 예방"으로 솔직히 인정하거나 다른 예시 보강.
- 요청 전송 도구(Postman/curl) 안내 부재 — 실무0 독자 (CS·부트캠프·Python).

### v2 압축 부작용 (내 overhaul)
- 위 "나머지 메서드도 같은 식으로" (코드 사라짐).
- **3.4 Checked/Unchecked 2문장 압축** — PM·Node·부트캠프가 "컴파일러·try-catch·throws가 한 문장에 몰려 튕김/추상적". 한 겹 풀어주거나 짧은 예시.
- 그림 3-3 "@RestControllerAdvice가 가로채 JSON으로" 본문 L283·L305 + 캡션 L336 = **3회 반복** (CTO).

### 낮음
- `orElseThrow(() -> new ...)` 람다 이유(지연 생성) 미설명 (Node).
- `findById(int)` vs 서비스 `Integer` 오토박싱 혼용 (Android·CS·DBA).
- Resp.fail의 HTTP 헤더 status와 body의 status값 구분 흐릿 (시니어).
- 그림 3-4 `[CAPTURE NEEDED]` 미생성 (출간 전).
