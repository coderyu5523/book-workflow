### 6. (경미) 2장 L703 캐싱 정의

- 원문: "캐싱은 … **똑같은 엔티티를 다시 요청할 때** 데이터베이스를 거치지 않고 바로 반환하는 기능입니다."
- 수정안: "캐싱은 … **같은 엔티티를 기본 키로 다시 조회할 때** 데이터베이스를 거치지 않고 바로 반환하는 기능입니다."
- 이유: DB를 거치지 않는 건 find()(기본 키 조회)뿐이다. JPQL 조회(findAll)는 같은 엔티티가 있어도 SELECT를 실행한다. 그림 2-18·2-19는 find()라 정의만 넓다

### 7. (경미) 5장 L270 지연 로딩

- 수정안: "**처음 접근할 때**" / "**접근하는 엔티티 수만큼**"
- 이유: 지연 로딩 객체는 처음 접근할 때 한 번만 조회한다. "getter를 부를 때마다 DB 조회"로 오해하게 된다
- 주의: 둘째 문장은 문장 검수 때 표현 기준 원문 유지였다. 이번은 한 단어만 바꾼다

### 10. (경미) 2장 L428 실습 1 코드 주석

- 원문: `@Id // 기본 키. DB가 자동으로 1씩 증가시켜 채운다` (다음 줄 `@GeneratedValue`에는 주석 없음)
- 수정안: `@Id // 기본 키` + `@GeneratedValue(strategy = GenerationType.IDENTITY) // DB가 자동으로 1씩 증가시켜 채운다`
- 이유: 자동 증가를 정하는 건 @GeneratedValue(IDENTITY)다. 완성 코드도 @GeneratedValue 줄에 "// 자동 증가" 주석이 있다

- 2장: H2 "메모리에서만"(책 설정은 mem), 테이블 칸에 단순 값만(관계형 원칙), 카멜→스네이크를 하이버네이트가 변환(실제 설정 주체는 부트), "JPA에는 수정 메서드가 없다"(EntityManager 메서드 기준, JPQL update는 쿼리), flush를 커밋 시점으로만 설명, 롤백 대상이 런타임 예외뿐인 점 생략, @Transactional을 롤백 장치로만 설명
- 3장: HTML/JSON 구분을 "브라우저/API 요청"으로(실제 기준은 Accept 헤더), /error "다시 요청"(내부 포워드), orElseThrow "인자로 전달한 예외"(실제는 람다), 요약 박스 "테이블이 바뀌어도 형식은 영향 없음"
- 4장: JPQL 기본 조인은 "FROM 절 엔티티만"(책 예제는 select b라 동일), "한 번의 조회로 가져와야"(설계 선택), JPQL은 필드명만(on 생략), Base64(실제 Base64URL), 필터 통과 조건에 만료 생략
- 5장: 양방향이라 조인으로 한 번에(선배 대사·프롤로그 L79), mappedBy "한쪽 어노테이션", N+1 "게시글 수만큼"(더미 데이터 2건·작성자 2명이라 실제 로그와 일치), 즉시 로딩 "한 번에"(바로 뒤가 별도 쿼리 설명), 작성자는 항상 존재해 INNER JOIN, 4장(EAGER)·5장(LAZY) 일반 조인 설명 차이(각각 맞음), 프롤로그 "조인으로 한 번에"(fetch join 요약)
