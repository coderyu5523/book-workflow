## 심각도별 이슈

### 높음 (독자가 실제로 막힘)
- **checked 예외 컴파일 실패** (실습 5·8·findUri): 8:2 이해 중심이라도 손으로 따라가는 독자는 첫 리플렉션 실습에서 "Unhandled exception type"으로 멈춤. 완성본과 불일치라 "막히면 spring-end 비교"가 오히려 "왜 완성본엔 throws가?" 혼란을 부름. **방어코드 제외 규칙과 자바 checked 예외 문법이 충돌**하는 지점.
  - 해결 옵션: (a) 예외 던지는 메서드 첫 등장 시 최소 try-catch를 코드에 노출, (b) 스켈레톤 시그니처에 `throws`를 미리 넣고 본문에서 "invoke는 예외 선언이 필요해 IDE가 요구합니다" 한 줄 안내.

### 중간 (혼란스럽지만 진행 가능)
- 1.7 용어·수치 과부하 (9/10 지적). CTO·시니어: 풀링/DBCP는 리플렉션과 무관한 인프라라 챕터 핵심에서 이탈 → 톰캣→DS→컨트롤러 호출까지로 좁히거나 후속 챕터로 이전 검토.
- **1.7 디스패처 서블릿 오개념** (시니어): "요청마다 컴포넌트 스캔·리플렉션으로 찾아 호출"로 읽힘. 실제는 기동 시 HandlerMapping 1회 구축 → 요청 시 조회(lookup) 후 리플렉션 호출만. 서술 보정 필요.
- "요청 풀링" 비표준 용어 (시니어): 풀링 대상은 요청이 아니라 워커 스레드(스레드 풀), 톰캣 기본 최대 200 → 50은 임의값.
- 1.5 클래스로더/.class 스캔 설명 얇음.
- **용어정리 표 부재** (CS학생·Java신입): 새 용어 10개+인데 챕터 끝 3열 회수 표 없이 `:::remember`로 마감. chapter-format 규칙상 기대 위치.
- **prep 파일 트리 불일치** (CS학생): 본문 `spring-start/ch01/exNN` vs 실제 레포 메이븐 구조 `src/main/java/com/reflection/exNN`. 파일 위치 혼동 소지.
- goal 박스에 "왜 손으로 만드나(마법 해체)" 존재 이유 부재 (CTO·Node) → 아크 설득력.

### 낮음 (개선하면 좋음)
- `rm.uri()` NPE 위험 (표식 없는 메서드 추가 시) — 예제는 안전하나 응용 시 지뢰, 경고 없음 (5명).
- `cls.newInstance()` Java 9+ deprecated + raw `Class` 경고 (6명) — 초보가 에러로 오해.
- if-else 한계가 오픈이의 체감 실패로 안 그려짐 (Try/Fail 약함) (4명).
- Node: 1.2 "이름을 몰라도 호출"이 동적 언어엔 당연 → 정적/컴파일 대비 부재. 제목을 "호출부를 안 고치고"로 무게 이동 제안.
- 캡처 desc "구분선 아래 delete 호출됨" vs 책 코드 구분선 없음 (Java신입).
