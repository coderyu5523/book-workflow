## 뼈대 병합 (스프링-뼈대 v1·v2 분석 기반)

v1(세션 블로그·개념 친절)과 v2(REST API·Security+JWT)를 정독 분석. 흐름은 v1, 코드는 완성코드/v2, 개념은 둘 병합. v1 폴더 번호≠교육순서(챕터1→3→2→4→5).

- **① CH4 인증 (확정)**: Spring Security **제거**, **JWT만** 사용(완성코드 기준: 필터=인증, 인터셉터=인가). v2의 Security(SecurityConfig·UserDetails·@AuthenticationPrincipal·hasRole)는 다루지 않음. v2에서는 JWT 유틸·로그인 로직만, v1에서는 개념(Stateless/Stateful·쿠키·인증vs인가)만 차용.
- **② 테스트 (확정)**: **단위 테스트만** 다룸. 통합 테스트(MockMvc)와 v2 바이브코딩 테스트 챕터는 보류·제외. (seed의 "단위·통합" → "단위만"으로 축소)
- **③ 범위 밖 (확정)**: 관리자 역할/권한(게시글삭제·역할수정), 바이브코딩·Spring REST Docs 문서 자동화 **제외**. 유저네임 중복체크는 완성코드에 엔드포인트 없음 → 자동 제외.
- **REST API 이론 도입부 (확정)**: CH2.1에서 "우리가 만들 건 REST API다 + HTTP 메서드" 짧게. URI 설계 규범은 제외.
