## 중간 (개념 오해 또는 혼란 유발)

### [CH2-2] exec 셸에서 exit/detach 동작 미구분

- **위치**: ch2 라인 418
- **의도**: commit 전에 컨테이너에서 빠져나오기
- **실제**: `exec`로 들어간 셸에서는 `exit`해도 컨테이너 유지됨. 그런데 2.4.1에서 "exit는 컨테이너 종료, CTRL+P,Q는 연결만 끊기"라고 배웠으므로 독자 혼동
- **수정**: "exec로 만든 셸에서는 exit를 입력해도 컨테이너가 유지됩니다" 한 줄 추가

### [CH2-4] "다 날아갔다" 서술이 실제 동작과 불일치

- **위치**: ch2 라인 255~259
- **의도**: 컨테이너 생명주기 위기감 조성
- **실제**: exit로 종료된 컨테이너는 `docker ps -a`에 남아있고 `docker start`로 재시작 가능. 데이터 소실 아님
- **수정**: "컨테이너가 꺼졌어!"로 수정하거나, "`docker ps -a`로 보면 종료 상태로 남아있어" 보충

### [CH2-6] 바인드 마운트가 호스트 폴더를 자동 생성한다고 설명

- **위치**: ch2 라인 486~497
- **의도**: 바인드 마운트 실습
- **실제**: `--mount type=bind`는 호스트 경로가 없으면 에러 발생. "폴더가 생성됩니다"는 잘못된 설명
- **수정**: 실습 전에 `mkdir -p C:/app/bind` 안내 추가, 또는 `-v` 문법으로 변경

### [CH3-1] depends_on 설명 vs EX07에 미사용

- **위치**: ch3 라인 535 + code/ex07/docker-compose.yml
- **의도**: Compose의 핵심 이점으로 "depends_on 기반 순서 보장" 강조
- **실제**: EX07 docker-compose.yml에 depends_on이 전혀 없음. 동작하는 이유는 Gradle 빌드 3~5분 소요 때문
- **수정**: EX07에 `depends_on: [db]` 추가, 또는 "EX07은 빌드 시간 덕에 순서 문제가 없지만 실무에서는 depends_on 필수" 부연

### [CH3-2] EX02 라운드 로빈 실습에서 시각적 구분 불가

- **위치**: ch3 라인 355~363 + code/ex02
- **의도**: 새로고침마다 두 서버가 "번갈아" 응답하는 것을 보여줌
- **실제**: 동일 이미지 2개라서 브라우저에서 동일 화면. 로그로만 확인 가능
- **수정**: app1/app2 index.html을 "Server A"/"Server B"로 분리, 또는 "로그에서 확인" 안내 추가

### [CH4-1] "순차적 교체"라고 설명하지만 maxSurge: 4로 전체 동시 생성

- **위치**: ch4 라인 436, 438 + code/yaml/deploy-ex02.yml
- **의도**: 롤링 업데이트 = "한꺼번에 바꾸지 않고 순차적으로 교체"
- **실제**: maxSurge: 4 + replicas: 4 = 새 Pod 4개 동시 생성 후 기존 4개 종료 (blue-green 스타일)
- **수정**: maxSurge: 1로 변경하여 진짜 순차 교체, 또는 "maxSurge 값에 따라 동시 생성 수가 달라진다" 명시

### [CH4-4] deploy-ex03.yml에서 secretRef가 주석 처리

- **위치**: ch4 라인 831~840 + code/yaml/deploy-ex03.yml
- **의도**: Secret을 Pod에 주입하는 방법을 가르침
- **실제**: Github 코드에서 secretRef가 `#` 주석 처리. 독자가 그대로 apply하면 Secret 미주입
- **수정**: 코드에서 주석 해제, 또는 챕터에 "주석을 해제합니다" 안내 추가
