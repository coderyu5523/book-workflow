## 심각도별 이슈

### 높음 (독자가 막히거나 혼란)

**1. CH4 분량 과다 (9/10명 지적)**

Pod, Deployment, ReplicaSet, Service, ConfigMap, Secret, Ingress, Namespace, PV/PVC, 풀스택 배포, 트러블슈팅이 한 챕터에 전부 들어 있다. CH4 단독 1,519줄로 CH2+CH3 합산과 맞먹는다. 초보~중급 페르소나 모두 "후반부 피로감"을 호소했고, CTO/테크리드도 분리를 권장했다.

> 제안: 4.1~4.4 (Pod~Service)와 4.5~4.7 (ConfigMap~풀스택+트러블슈팅)로 분리하거나, 최소한 중간에 "여기까지 이해했으면 쉬어가세요" 구간 표시

**2. PV/PVC 개념 정의 누락 (8/10명 지적)**

db-deploy.yml에 `persistentVolumeClaim`이 등장하지만 PV/PVC가 무엇인지 본문에서 한 번도 정의하지 않고 "Github을 참고합니다"로 넘어간다. CH2에서 바인드 마운트/볼륨 마운트를 다루었으므로, "2장에서 배운 마운트의 K8s 버전"이라는 브릿지 한 단락이 필요하다.

**3. 그림 번호 5-N 혼재 (6/10명 지적)**

4장 네트워크 돋보기 안에 "그림 5-1" ~ "그림 5-6"으로 번호가 매겨진 그림이 있다. 이 책은 4장까지이므로 5장 번호는 오류다.

**4. 바인드 마운트 경로 Windows 전용 (6/10명 지적)**

`src=C:/app/bind` 경로가 Mac/Linux 독자를 위한 대응 경로 안내 없이 Windows 전용으로 되어 있다.

### 중간 (혼란스럽지만 진행 가능)

**5. EX07 Gradle 빌드 시간 미명시 (6명)**

"수 분 소요"만 있고 구체적 시간(예: 3~5분) 없음. 초보 독자가 "멈춘 건가?" 불안해하며 Ctrl+C를 누를 위험.

**6. vim 사용법 안내 부족 (4명)**

i → 입력 → ESC → :wq 플로우가 한 줄 안내뿐. VS Code만 쓰던 독자가 당황. 부록 참조를 더 눈에 띄게.

**7. Docker Hub 계정 사전 안내 부재 (4명)**

`<본인-dockerhub-id>` 등장 시점에 계정 생성 방법/링크 없음.

**8. 이모지(💪) 잔존 (4명)**

"직접 해보기" 섹션에 이모지가 남아있음. 스타일 규칙(이모지 전면 금지) 위반.

**9. 네트워크 돋보기 난이도 안내 (3명)**

비개발/초보 독자에게 "지금 이해 안 되어도 실습에 지장 없다"는 한 줄 안내가 있으면 심리적 부담 감소.

**10. 비밀번호 평문 노출 경고 (3명)**

`SPRING_DATASOURCE_PASSWORD: root1234`가 docker-compose.yml에 하드코딩. "운영에서는 이렇게 하면 안 됩니다" 한 줄 필요. CH4 Secret으로의 브릿지 문장으로 활용 가능.

**11. Chocolatey/Homebrew 사전 안내 (3명)**

minikube 설치 전제 조건인데 설치 안내/링크 부족.

**12. minikube tunnel 새 터미널 안내 (3명)**

tunnel이 포그라운드로 터미널 점유. "새 터미널을 열어야 한다"는 안내가 뒤늦게 등장.

### 낮음 (개선하면 좋음)

**13. CH2 "이것만은 기억하자"에 CH3 내용 (3명)**

Dockerfile/밀키트 언급이 CH2 요약에 등장하지만 CH2에서는 Dockerfile을 다루지 않음.

**14. CH4 후반부 이야기 급감 (3명)**

4.1의 강렬한 도입 이후 4.3부터 기술/YAML 위주로 전환되면서 이야기적 전환 장치 부족.

**15. EX03 누락 (1명)**

EX01 → EX02 → EX04로 점프. EX03이 건너뛰어진 이유 불명확.

**16. depends_on 한계 미언급 (1명, DevOps)**

컨테이너 시작 순서만 보장, 애플리케이션 ready 상태 미보장이라는 점 한 줄 필요.

**17. entrypoint.sh git clone 실패 가능성 (2명)**

EX07 백엔드가 컨테이너 내부에서 git clone + gradle build를 하는 구조. 네트워크 문제 시 실패하고 트러블슈팅 안내 없음. 또한 CTO가 "실무에서는 이 패턴을 쓰지 않는다"는 한 줄 필요 지적.

## 전체 평가 요약

### 강점 (전원 공감)
- **"네트워크 돋보기" 시리즈**가 이 책의 결정적 차별점. Docker→K8s로 DNAT/DNS/Bridge 개념이 일관되게 확장
- **비유→정의 2단계** 구조가 모든 배경의 독자에게 효과적
- **"문제→해결" 서사** 반복으로 각 도구의 필요성이 자연스럽게 체감
- **실패 먼저** 패턴 (Tomcat 404, 세션 불일치 등)이 교육적으로 효과적
- **CTO/DevOps**: "기술적으로 정확하고, 팀 주니어에게 자신 있게 추천"

### 약점 (다수 공감)
- CH4 분량이 다른 챕터의 2배 이상으로 후반부 피로감 큼
- 환경 설정 안내(Docker Hub, Chocolatey, OS별 경로) 곳곳에서 부족
- PV/PVC 같은 핵심 K8s 개념이 코드에만 등장하고 정의 누락
- 그림 번호 오류, 이모지 잔존 등 편집 이슈

### 핵심 수치
- 전체 통과율: **10/10명**
- 평균 점수: 이야기 **4.5**/5 | 기술 **4.3**/5 | 실습 **4.0**/5
- 가장 높은 챕터: **CH3** (기술 4.7, 이야기 4.5)
- 가장 낮은 실습 점수: **CH4** (3.6) — 분량 과다 + 환경 설정 허들
